Last updated: 2026-09-14

Current state

The week added no new method here but sharpened a live attribution question. The provenance dispute around OpenAI's claimed Navier–Stokes result now has a checkable fact attached: NYU mathematician Tristan Buckmaster and Anthropic researcher Levent Alpöge published a closely related fluid-equations result one day before OpenAI's announcement, and researchers circulating the comparison allege OpenAI drew on a year of user-submitted mathematics before finishing the work with Astra. The allegation travels as social posts rather than as a filing and is unproven; the concurrent publication is verifiable, and it converts a complaint about tone into a question about priority that a referee could actually adjudicate. It also sits awkwardly beside the Fermat proof recorded below, where the artifact is a machine-checkable Lean development and priority is therefore not in dispute — the contrast is a reasonable working test for claims in this area. The cycle's own contribution is an inference about a closed model rather than a result from an open one. Sebastian Raschka argues (Sep 10) that GPT-6 Astra most likely uses a variant of the looped transformer — reusing a block of layers for a variable number of passes instead of stacking depth — buying better modelling performance at a fixed compute budget and moving computation inside the architecture rather than across emitted tokens, with computer use the capability where the leap is largest. The reading that changes how the model should be handled concerns its unusually short reasoning traces: on this account brevity is a symptom of a model making fewer mistakes and reasoning internally, not a trained stylistic preference, so trace length now says much less about effort than it used to. He is explicit that this is inference from published behaviour, not disclosure. Set beside the recurrent-depth concern, the two describe one property from two sides — the architecture that improves performance per unit of compute is the architecture that moves reasoning out of the artifact a monitor can read. It shares that discipline with the August papers carried here for how sharply they bound their own claims. Specula automates bug finding by writing a specification rather than reading code — deriving TLA+ specs from an implementation, validating conformance by trace, model-checking for concurrency bugs, then reproducing each at the code layer as an integration test with the timing needed to trigger it. The accompanying analysis is unusually direct about the limit: it works for what it does, but it sidesteps composition, so it says nothing about whether per-module guarantees add up to a system-level guarantee. That is exactly where formal verification has always stopped, and naming it is more useful than the tool. The second is a static retrieval model trained on 660 million pairs and quantized hard enough to fit in 8MB, which embeds the whole of English Wikipedia on a laptop in under eight minutes. Static embeddings give up the contextual sensitivity of a transformer encoder; what comes back is retrieval with no serving infrastructure, no GPU and no per-query cost, which changes which applications can justify retrieval at all rather than making existing ones better. The headline result of the previous cycle was also the one with the largest asterisk. OpenAI says an internal system resolved the Navier–Stokes existence and smoothness problem, showing that smooth three-dimensional fluid dynamics can develop a finite-time singularity, and produced both an analytical proof and a Lean formalization — reportedly from about 10,000 agents exchanging 2.7 million messages and generating 130 billion output tokens over 88 hours. It has not been independently reviewed or accepted by the Clay Mathematics Institute, and NYU's Tristan Buckmaster says his team had already fed related unpublished drafts into OpenAI's Codex, with OpenAI declining to say whether those drafts entered training data. Coming two days after Claude's computer-verified Fermat proof, the pair mark a real change in what these systems produce and, simultaneously, the moment the field's evaluation machinery stopped being adequate to check it: a Lean formalization proves the argument is valid, not that the argument was the model's to make. Provenance is now the load-bearing question in AI mathematics, and no lab currently publishes enough to answer it. DeepMind's AlphaGenome Atlas makes the opposite kind of contribution — one petabyte of precomputed predictions covering the regulatory effect of all 9 billion possible single-nucleotide human variants, each with a single impact score, queryable without writing code or running the model. Shipping a model as a lookup table is a distribution decision rather than a research one, and it is the decision that determines whether a genomics lab without an inference budget can use the work at all. On architecture, two quieter items push at the same constraint from different budgets: Microsoft's full-bandwidth transformers feed the previous token's top-layer hidden state back in alongside the next token embedding so latent computation survives the token boundary — an extra input rather than a rewrite — and a detailed walkthrough of Thinking Machines' Inkling documents a frontier model that admits images and audio with no separately pretrained encoder in front of them, which is a rare fully specified alternative to the standard bolted-on vision tower. The decoding-side result worth carrying forward this cycle is Speculative Programmatic Tool Calling: predict the likely tool calls from partially generated code and launch them early, so searches, sub-agents and API calls run alongside token generation rather than after it. The authors frame it as a JIT compiler for the agent loop and report a 1–1.2× runtime speed-up, concentrated exactly where the overlap is real — memory-bound local models and high-volume serving. The modest multiplier is the honest part: this is a scheduling win, not an architectural one, and it only pays where tool latency and generation latency are comparable. Before it, two August papers share a shape: both take a task an LLM does badly in one pass and decompose it into an evaluate-then-act loop. Agentic ASR (Shanghai Jiao Tong, Zhejiang, Fudan, Xiaoice) stops asking a model to rewrite a transcript and instead has it classify each turn as confirmation, addition, or correction, then locate the span, infer the intent, and apply the edit — an editor rather than a rewriter — cutting semantic error from 21.5% to 3.5% on GigaSpeech and 28.6% to 1.4% on code-switched ASRU2019 over ten turns. Stanford's SecureForge applies the same separation to code security, using the GEPA genetic algorithm with a static analyzer's vulnerability reports as the fitness signal to evolve the developer-editable system prompt, and halving vulnerable output (11.8% against 20.1%) relative to simply asking for secure code and naming the risks — across ten models from CodeLlama 7B to Claude Sonnet 4.6. The same decomposition shows up in the clinical trial on the Applications page, where splitting each turn into an evaluate call and a generate call is what stops the model agreeing with the user instead of challenging them. The method set now spans two poles: infrastructure-flavoured work that makes existing models cheaper, more trainable, or better grounded, and — newly — a domain foundation model showing the self-supervised JEPA recipe scaling on raw, unlabeled real-world data. That newest result is NeuroVFM, a neuroimaging foundation model from the University of Michigan trained with Vol-JEPA (a volumetric joint-embedding predictive architecture in Yann LeCun's JEPA line) on 5.24M uncurated clinical MRI and CT volumes — pulled straight from hospital systems with no radiology-report labels and no curation — learning anatomy and pathology directly from raw data; published in Nature Medicine with open weights, it is a template for turning idle clinical archives into foundation models (medical-deployment angle on the Applications page). On the infrastructure axis, the standout architecture result is MiniMax Sparse Attention (MSA): a two-branch block-sparse attention (a local branch for recent context plus a global branch for long-range dependencies) that cuts per-token attention compute at 1M context by 28.4× versus dense GQA with on-par quality, yielding 14.2× faster prefill and 7.6× faster decode on an H800, trained on a 3T-token / 109B MoE. Crucially it is GQA-native, so it drops into existing architectures without a redesign — the kind of architecture-level result that tends to propagate into every long-context serving stack within a year (serving angle on the Infrastructure page). A second methodologically interesting release is Liquid AI's LFM2.5 embedding/ColBERT pair, built by patching a causal decoder into a bidirectional encoder rather than training a retrieval encoder from scratch — an unusual reuse of a 28T-token generative pretrain that nonetheless beats larger dedicated embedding models (model detail on the Model releases page). These join the standing method set: NVIDIA Polar (RL on black-box coding agents), EAGLE 3.1 (speculative decoding without attention drift), Harness-1 (RL trained inside a stateful search harness, see Training & RL), and Flash-KMeans, an IO-aware exact K-Means that applies the FlashAttention "redesign-around-GPU-memory" recipe to a classical clustering primitive for ~200× speedups over FAISS. The July embodied-AI wave added two architecture ideas worth tracking as methods: Robbyant's LingBot-VA 2.0 interleaves video and action tokens in one causal sequence via a Mixture-of-Transformers and re-grounds on the robot's real observation every step (a "predict-while-acting" loop that reportedly beats π0.5 on long-horizon manipulation), while LingBot-World-Infinity wraps a causal world model in an agentic harness — a pilot agent plans while a director agent seeds the environment — importing the coding-agent "model + harness" pattern into world modeling (full detail on the Embodied AI & robotics page). The empirical standout remains a Perplexity/Harvard field study of autonomous agents versus chat in real knowledge work: over three months, workers using an autonomous agent finished tasks in 87% less time at 94% lower cost than search alone, with higher satisfaction — a rare quantified measurement of agent productivity beyond benchmark scores. Framing the architecture side, a July 15 interview with Sebastian Raschka (tied to his new 440-page book on LLM architecture) reads the 2026 landscape as three converging shifts: inference-time scaling moving capability from the weights into the agent harness around them, hybrid architectures (attention interleaved with state-space / linear-attention layers) becoming the long-context default, and fine-tuning economics collapsing far enough that open models now set the pace at which ideas spread across the ecosystem.

Self-supervised & domain foundation models

NeuroVFM (University of Michigan, Nature Medicine) is a neuroimaging foundation model trained with Vol-JEPA — a volumetric extension of Yann LeCun's joint-embedding predictive architecture — on 5.24M raw clinical MRI and CT volumes. The methodological point is the training data: no radiology-report labels and no curation, just the uncurated volumes hospitals already store, with the model learning anatomy and pathology self-supervised in embedding space rather than pixel space. It is evidence that the JEPA line scales to messy 3D medical data, and a template for converting idle clinical archives — labels have always been the bottleneck for medical AI — into generalist foundation models. Weights are open. (Deployment/economics angle on the Applications page.)

Agent productivity studies

Perplexity, with Harvard, studied the shift from chat interfaces to autonomous agents (its "Computer" agent) in real knowledge work over three months. Headline findings: 87% less time and 94% lower cost per task versus search alone, with higher reported satisfaction. The value is the field-study methodology — measuring outcome time/cost on real tasks rather than static benchmarks. (Applied angle on the Applications page.)

Attention & long-context architecture

A method line attacks the quadratic cost of attention at long context directly, at the architecture level rather than the serving layer. MiniMax Sparse Attention (MSA) uses two branches — a local branch over recent context and a global branch for long-range dependencies — to make attention block-sparse, reaching a 28.4× reduction in per-token attention compute at 1M context versus dense grouped-query attention (GQA) with quality reported on par. Measured on an H800 that translates to 14.2× faster prefill and 7.6× faster decode; it was trained with a 3T-token budget on a 109B-parameter MoE. The portability claim matters most: MSA is GQA-native, so it can replace the attention block in existing GQA architectures without a redesign, which is why it is plausible this becomes a default in long-context serving stacks. (Serving-cost angle on the Infrastructure page.)

Retrieval-model architecture

An efficiency-minded line builds retrieval models by repurposing existing generative pretrains instead of training encoders from scratch. Liquid AI's LFM2.5-Embedding-350M (dense bi-encoder) and LFM2.5-ColBERT-350M (late-interaction) were both produced by patching LFM2.5-350M, a causal decoder, into a bidirectional encoder — an unusual move that converts a model pretrained on 28T tokens into a retrieval model and, per the release, yields retrieval quality beating larger dedicated embedding models. The two architectures span the speed/precision trade-off (bi-encoder for speed, ColBERT late-interaction for precision) at the same 350M footprint. (Release and RAG-pipeline detail on the Model releases page.) August pushed the footprint question to its limit in the other direction: training on 660 million pairs and quantizing aggressively yields a static retrieval model of 8MB that embeds all of English Wikipedia on a laptop in under eight minutes. Static embeddings are a real concession — no contextual sensitivity, so a token's vector does not change with its surroundings, which is precisely what the late-interaction and matryoshka work above spends its parameter budget on. The trade is worth stating plainly rather than as a benchmark delta: the 350M models compete on retrieval quality per parameter, while an 8MB static model competes on removing the serving tier altogether. Below some corpus size and quality bar, no GPU, no index service and no per-query cost beats a better ranking, and this puts a concrete number on where that line now sits (see vector-index & RAG-pipeline economics).

Decoding & inference

EAGLE 3.1 builds on the EAGLE speculative-decoding line, addressing attention drift that had been undercutting acceptance rates. Speculative Programmatic Tool Calling (Aug 25) carries the same speculation idea out of the token stream and into the agent loop: rather than predicting tokens, it predicts tool calls from partially written code and pre-launches them, so retrieval, sub-agents and API work overlap with generation instead of queuing behind it. The reported 1–1.2× speed-up is deliberately unglamorous and the paper is clear about where it comes from — memory-bound local inference and high-volume serving, where there is genuine idle time to fill. The failure mode is the one speculation always has: a mispredicted call is work done for nothing, which matters more when the call has side effects than when it is a wasted forward pass.

IO-aware kernels & data-pipeline primitives

A method line generalizes the FlashAttention idea — redesign an algorithm around the GPU's real memory hierarchy rather than its FLOP count — beyond attention. Flash-KMeans applies it to exact K-Means: standard implementations (including FAISS) are IO-bound and waste cycles on redundant memory transfers, so Flash-KMeans rebuilds the algorithm with Triton kernels and batched, memory-efficient access patterns, yielding exact (not approximate) results at ~200× over FAISS, ~30× over cuML, and 17.9× end-to-end on an H200. Because K-Means underpins vector quantization, embedding clustering, and RAG index building, the result is directly useful for retrieval pipelines. (Serving/cost angle on the Infrastructure page.)

World models & embodied-policy methods

The embodied-AI wave produced two architecture ideas worth tracking as methods rather than just model drops. Robbyant's LingBot-VA 2.0 is an autoregressive diffusion policy that predicts while acting: it interleaves video and action tokens in a single causal sequence via a Mixture-of-Transformers, then re-grounds on the robot's latest real observation at every step, using a partial-denoising trick and an asynchronous inference pipeline to sustain high-frequency closed-loop control — reportedly beating Physical Intelligence's π0.5 on long-horizon and precision manipulation. Its sibling LingBot-World-Infinity attacks world modeling with an agentic harness: a pilot agent plans character behavior while a director agent seeds new environment elements, turning a frame predictor into a self-sustaining, hour-scale world without visual drift. Both port ideas from language-model agents — causal sequence modeling and the "model + harness" scaffolding pattern — into robotics. (Full detail on the Embodied AI & robotics page.)

RL on agents

NVIDIA Polar reconstructs token-faithful RL trajectories from API-level proxying, enabling GRPO across closed coding harnesses. Harness-1 trains a 20B retrieval agent with RL inside its search harness (0.730 curated recall, open weights/code), an environment-native counterpart.

Architecture analysis & practitioner synthesis

Not every notable writeup is a paper: some are syntheses that name where the architecture is heading. A July 15 interview with Sebastian Raschka — pegged to his new 440-page book on LLM architecture — argues that "implementation does not lie," i.e. you learn what actually works by building it. Its three throughlines map onto recurring threads elsewhere in this wiki: (1) inference-time scaling and the agent harness increasingly carry capability that used to live in the weights (see Agents and Tools & DevEx); (2) hybrid architectures that interleave attention with state-space / linear-attention layers are becoming the long-context default (the same direction as MSA above and NVIDIA's Mamba-Transformer Nemotron); and (3) fine-tuning economics have fallen far enough that open models are now the medium through which architectural ideas propagate. It is synthesis rather than a method release, but a useful map of the design space the method work is filling in. Two August additions belong here. A long walkthrough of Thinking Machines' Inkling — the lab's first from-scratch model, Apache 2.0 on Hugging Face — documents the architecture, position encoding, thinking-effort control and, most usefully, the decision to let images and audio enter the model without a separately pretrained encoder in front of them. Nearly every multimodal model in production does the opposite, so a fully documented counterexample is worth more than another benchmark table; read with the Inkling-Small distillation result on the Training page, it is now one of the better-specified frontier architectures in public. Cameron Wolfe's RL reference (Aug 24) is the other, and it is a synthesis rather than a result: the full policy-gradient lineage from VPG through REINFORCE, PPO and GRPO to DAPO, Dr. GRPO, GSPO, TIS and CISPO, with an argument that the post-GRPO variants are not new algorithms but refinements of loss aggregation, reward normalization, batch selection, clipping and per-token versus per-sequence importance ratios — details that only matter at scale, which is why they all appeared at once. Specula (Aug 13) is the cycle's clearest example of the analysis being more valuable than the artifact. The system derives TLA+ specifications from system code automatically, validates code-spec conformance through traces, model-checks the spec for concurrency bugs, and reproduces each finding at the code layer as an integration test with the timing needed to trigger it — which addresses the practical objection that has kept model checking out of ordinary engineering, that a spec-level counterexample is not obviously a real bug. The critique published alongside it does the harder work: Specula is a good pragmatic idea that works for what it does, and it skirts composition entirely, so it cannot say whether per-module guarantees compose into a system-level one. That is not an implementation gap to be closed in the next version; it is the open problem the whole field has been at for decades, and it is worth knowing which side of it a tool sits on before adopting it. Sebastian Raschka's Sep 10 reading of GPT-6 Astra is this section's other mode: inference about a closed model from its published behaviour. He argues it most likely uses a variant of the looped transformer — reusing a block of layers for a variable number of passes rather than stacking more depth — which buys better modelling performance at a fixed compute budget and lets computation happen inside the architecture instead of across emitted tokens, and he singles out computer use as where the improvement is largest. The inference that changes how the model should be read is about its unusually short reasoning traces: on this account brevity is a symptom of a model that makes fewer mistakes and can reason internally, not a trained stylistic preference, so the trace length tells you less about effort than it used to. Raschka is explicit that this is inference rather than disclosure. Read beside the recurrent-depth concern, the two describe one property from two directions: the same architecture that improves performance per unit of compute is the one that moves reasoning out of the artifact a monitor can read.

It attacks the same constraint as recurrent-depth designs and test-time training, from the cheapest possible angle: an extra input rather than an architectural rewrite or a per-user weight set.
