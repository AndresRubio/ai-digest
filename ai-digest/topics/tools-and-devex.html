Tools, IDEs & developer experience

Last updated: 2026-09-16

Current state

Today's cycle finishes the model-as-parameter argument and then quietly starts a different one about control. Apple's iOS 27 Foundation Models framework (Sep 15) exposes any language model — its own third-generation on-device models, or cloud models including Claude and Gemini — through a single Swift API, with Siri gaining App Intents and its own app. Model Delegation was code found in a binary and could have been a private arrangement; a documented framework is what every third-party app builds against, so the swap now runs the full height of the platform from IDE to assistant to app API. Anthropic's Claude Mods arrived the same day and points somewhere else. Its developer half is modest — TypeScript functions that change how Claude Code looks and behaves, from hiding values during a screen share to tracking token usage — but an admin can disable risky capabilities across a whole organisation, which is the first extension surface inside a vendor's own agent that answers what can be centrally removed rather than what can be added. A per-user config is advisory; anyone who can edit it can edit it back.

The cycle's numbers are all about who writes the code and what that costs. Anthropic says Claude now authors roughly 80% of its production code with the team shipping about eight times more — self-reported, undefined, no defect rate, and the third unaudited claim in a set that still has no independent member, though a share is at least falsifiable in a way a multiple is not. The measured counterpart came from a tool: Alibaba reports Open Code Review using about one-ninth the tokens of a general-purpose agent on the same review, by hard-coding the steps that need no judgement and leaving the rest to the model. Two Sep 15 releases put the harness itself back in the open-source column from opposite ends — Hugging Face's Tau, a terminal coding agent written to be legible rather than minimal, and Cline Desktop, which ships the harness as a product with open weights as the assumed backend rather than the fallback. And the cheapest item of the day is one line: CLAUDE_CODE_SUBAGENT_MODEL=opus stops Claude Code's subagents inheriting the session's frontier model, which is Spotify's routing insight at one developer's scale.

The question this page has circled all month — if agents write the code, what is the human doing? — got its most concrete answer yet, and it is auditing rather than reviewing. Simon Willison and Alex Garcia shipped Datasette 1.0a39 and 0.65.4 (Sep 11) as security releases after auditing the codebase with Claude Fable 5.1, GPT-5.6 and GPT-6 Astra. The ratio is the finding: the models surfaced genuinely subtle bugs, and confirming and fixing them took nearly a week of two people working together. Their split is worth copying — for most issues one person wrote the automated test demonstrating the bug and the other implemented the fix, so two humans saw every issue and the agents driving them ran different models. The expensive step is not reading the diff but constructing the evidence that a reported bug is real, and dividing it keeps one agent's confident summary from becoming the only record. Willison now treats frontier-model security audits as a permanent part of the process. Claude Code's new /diff panel (v2.1.260 and later, after /tui fullscreen, 110 columns minimum) is the small ergonomic version of the same principle: uncommitted changes beside the conversation, refreshing as the agent edits.

Model-agnosticism reached the last surfaces that could have resisted it. Xcode 27 (Sep 14) ships coding agents driven by any model, with a Device Hub and customisable agent configuration, and the same day Apple's new Siri turned out to carry Model Delegation, which registers Claude as a Siri extension exactly as ChatGPT already is. A tool's differentiation is no longer the model it bundles, because it does not bundle one: it is the integration surface — documentation fetched live, devices reachable, permissions enforced, review put in front of you. The cost-side corollary is on the Infrastructure page, where Spotify's Portal cut routine token spend roughly 90% by routing file reads to a cheaper model; once the model is a parameter, choosing a smaller one per task is configuration rather than migration.

Earlier cycles

The starker item is an architecture decision running backwards. Shopify is moving off React Native (Sep 10) to separate Swift and Kotlin codebases after six years, and it is scrupulously fair about what it is leaving: the 2020 reasons — build each feature once, work across the stack, stop chasing parity — still describe real costs of going native, and none has gone away. What changed is that agents now absorb enough implementation, translation, testing and review that duplication stopped being decisive. Every abstraction argument in software assumes writing the same thing twice is the expensive part; when that collapses, unifying layers lose their justification and platform-specific code becomes affordable again. Shopify maintains react-native-skia, flash-list and restyle, two of which are being rehomed — so one company's read of agent economics reallocates maintenance for an ecosystem outside it.

This cycle is about what a coding agent is allowed to touch and who checks it afterwards. The sharpest number comes from review practice: Gergely Orosz's survey of teams drowning in agent-written PRs found the durable strategy is triaging by blast radius rather than by diff size, and Duckbill Group's five-engineer team — stuck at 60 open PRs — rebuilt around it, requiring a human only for changes touching auth, public APIs, database schema, design systems or agent skills and letting automated checks clear the rest. Weekly merges went from 80 to 154 and low-risk PRs merged in about an hour against 26 hours; OpenAI and Anthropic run the same policy. Nobody has published the defect rate on the fast path, which is the number that would settle it.

Extensibility took a real step the same day: Google's Cloud Developer plugin bundles live documentation, guardrails and gcloud handling behind the open Agent Plugins specification, so one bundle loads into Antigravity, Claude Code and Codex alike, and Google Maps shipped skills on the same principle — both fetch current docs while generating code instead of trusting what the model memorised, which is the practical answer to an API that moves faster than a training run. Alibaba open-sourced Open Code Review, the review agent it ran internally for two years across tens of thousands of developers, notable less for its design than for arriving with a production history attached. Google's Artemis hands a coding agent a real Android phone over MCP, for cross-app workflows, Logcat crash collection and exploratory runs past ten hours. Two smaller tools close the loop on knowing what you are running: npx geiger-scan inventories every agent, MCP server, plugin, hook and browser extension on the machine and labels which can execute code, read the filesystem, reach the network or hold credentials — with the config line that caused each finding — and llmfit ranks open models against your actual CPU, RAM and VRAM, accepting submitted real-world tokens/sec that then replace the estimate for everyone on the same hardware. And a one-line Codex config change, experimental_mode under [features.context_management], replaces end-of-context compaction with notes the model writes and searches — fixing the specific failure where compaction keeps a decision and discards the reason for it.

Before this cycle, four items were about the developer's job rather than the developer's tools. AWS's Clare Liguori argues under the name frontier engineering that nearly every team now has coding agents and almost none ship faster, because the split that matters is between teams that swapped tools and teams that changed the work: the second group builds the agentic system that builds the software and writes under 1% of shipped code by hand. Her ten principles reduce to writing intent rather than code, making the environment do the supervising through fast local test loops and machine-readable docs and tight permissions, and delegating broadly while discarding output that misses instead of repairing it — with the honest note that the first weeks feel slower and the payoff arrives as the deferred re-architecture finally becoming affordable. Lauren Tan's pstack part 2 supplies the unit of work that follows from it: against elaborate plan documents, which are progress-shaped rather than progress, small changes you have actually verified and are willing to throw away. Both fall out of the same arithmetic — if verifying a change is the expensive step, changes stay small enough that verification stays cheap.

The two products alongside them fill in gaps that follow from the same shift. Traycer sells the seam between vendors, running Claude Code, Codex, OpenCode and Cursor in one workspace with handoff and shared history, because a developer paying for three subscriptions can drive one at a time and the context that justifies all three is stranded in whichever client made it. And ZeroModels ships a pretrained collection written entirely in Keras 3 — classification through VLMs and speech recognition — that runs on JAX, PyTorch or TensorFlow with neither transformers nor torch at runtime, which turns the serving framework back into a deployment choice rather than something inherited from whichever checkpoint was picked first.

Cursor's August platform moves are the precedent for all of it: Cursor Builds (Aug 14) prepares development environments in the background so cloud agents wake into a ready one, up to 3x faster at no extra cost and falling back to the last good build while a developer debugs the broken one — on the premise that the binding constraint on a cloud coding agent is the environment it wakes into, not the model driving it. Meanwhile Origin looks set to leave its closed partner beta as Cursor Review (Aug 12), adding a Codebase tab that syncs repositories pulled from GitHub and a Review tab running an automated pull-request pipeline that interrupts a developer only when their judgment is actually required. That is the second front in the move from editor to code host, and it lands against a GitHub already repositioning around the parts of development that are not writing code. Anthropic made a quieter version of the same consolidation: Claude in Chrome's side panel (Aug 13) now runs a full Cowork session, with conversations saved to the account and resumable on desktop, web or mobile and existing skills and connectors working in the browser with no separate setup — the browser stops being a distinct product surface holding its own state and becomes another window onto one session.

The previous cycle's two most useful releases were notable instead for how little they weighed. Vercel's gpu-lexer classifies code tokens through WebGPU with a 27.5 KB model and no language hint, disagreeing with Shiki on 12.57% of tokens in held-out files — not good enough to replace grammar-based highlighting, and precisely the point: a tiny model is displacing a large body of hand-written language rules in a place where the rules were assumed to be free. Rapid-MLX makes the same argument about hardware, serving Qwen3.5-4B at 61 tokens per second in about 6 GB on a base M4 Mac mini, exposing it through an OpenAI-compatible API so Cursor, Claude Code and Aider point at it unmodified, and shipping a recipe command that inspects the machine and names the strongest model that fits. Unsloth's Dynamic 3.0 GGUFs attack the same frontier from the calibration side, reporting up to 10% better top-1% accuracy at unchanged file size from a refined imatrix dataset and no quantization-aware training — concentrated at the small quants, which is exactly where 4-bit survives and 1-bit collapses.

The vendor releases moved the other way, toward central control. Google put Antigravity into Gemini Enterprise subscriptions with extensions for VS Code, Visual Studio, JetBrains and Zed, and set sandbox, tool-permission, budget, identity and audit controls administratively; its Custom Agents (Aug 17) are file-based roles with scoped instructions, tools and constraints, kept deliberately distinct from skills and dynamic subagents. Warp's Agent Memory preview goes further than anyone else by sharing persistent memory across harnesses, machines and teammates, which is why each item carries provenance — a fact one person's agent run invents becomes everyone's context otherwise. Two items sit outside the agent story and are worth keeping anyway: Mojo was open-sourced under Apache 2.0 with LLVM exceptions, having formally abandoned the Python-superset goal in August 2025 and become its own GPU-oriented language; and MathCode pairs a coding agent with a Lean 4 formalization engine, a persistent Lean REPL and reusable theorem libraries, on the reasoning that proof search is only affordable when earlier work is retained rather than rebuilt each session.

The clearest number of the cycle is a routing result. A Spotify engineer's shunt plugin cuts Claude Code token use by roughly 90% in Java testing workflows by sending bulky file reads and predictable generation to Gemini 2.5 Flash and keeping Claude for the hard parts — one engineer, one workload, and 10 to 30 seconds of added latency per handoff, but the mechanism is general. ripwire attacks the same cost from the other side, building a deterministic offline code map — symbols, dependencies, churn, complexity, likely tests, no embeddings and no index server — so the agent spends context on the change rather than on orientation. Two more terminal agents shipped with the sandbox on by default: Meta's Muse Code for the terminal and CI, and Z.ai's ZCode with parallel tasks, scheduled recurring work and mobile control of a running session. Around them, the plumbing got less forgiving of neglect: GitHub Agentic Workflows puts agents behind the same event triggers and schedules as CI with Copilot, Claude Code, Gemini or Codex as the engine; Google's Accelerator Agents automate PyTorch→JAX migration and Pallas kernel work, which is the developer-experience half of selling TPUs to people outside Google; Firecrawl's anydoc added OCR at a 190ms median per scanned page with no API key; and Vercel's Run SDK evaluates untrusted TypeScript in QuickJS on a worker thread, which is the sort of narrow, checkable boundary the VM-escape results keep arguing for. Two Claude Code fixes belong in the same paragraph because they are the same kind of bug — a setting that behaves differently at hour six than at minute one: tool definitions were being re-rendered after OAuth refreshes, forcing a prompt-cache miss about once an hour, and allow-list wildcards written for one project silently extended to the same command anywhere on the machine.

Before all of it, the harness had started improving itself from its own history. Warp's Skill Doctor reads past Claude Code, Codex and Warp transcripts, scores where the agent worked well or wasted effort, and emits diffs against the skill files that shaped it — backed by a feedback loop across 10 million Claude Code sessions in which a separate agent converts user corrections into small skill edits, so a correction outlives the session it was made in. Microsoft's AutoSaddler does the same from execution traces rather than user feedback. Both inherit the month's central hazard: a harness tuned against a measurement optimizes that measurement, and the spreads on Evals show how much room that leaves without touching the model. A quieter cluster addresses what agents cannot see — Repomix packing a repo into a structure-preserving bundle with secret scanning, Chrome DevTools MCP handing coding agents real console, network and DOM state instead of screenshots, and only-cli and OpenKB arguing that HTML pages and embedding indexes are both wasteful encodings for an agent to consume.

Two releases attack agent security from the side policy cannot reach. Vercel Connect replaces long-lived API tokens with credentials issued at runtime, scoped to one task and expiring automatically — the credential half of the problem the rogue-agent escape on Safety & policy exposed, where damage scaled with how long agents retained reach they should not have had, and the first mainstream answer treating agent access as ephemeral by construction. WebMCP in ChatGPT comes at it from the other end: a site can hand an agent callable tools instead of forcing it to infer its way through a human interface, which removes a whole class of misinterpretation and makes the agent experience something site owners design rather than something that happens to them. Microsoft's AutoSaddler then closes the loop by reading execution traces and rewriting prompts, tools and middleware automatically — harness engineering as a search problem, inheriting the month's central hazard, since a harness auto-tuned against a benchmark optimizes the score without touching the model.

August's clearest signal is that the model under a harness is becoming a swappable part, and both directions of the swap shipped. Ollama can now configure Claude Desktop to use it as a third-party gateway, pointing Anthropic's own harness at any local model or any model on Ollama's cloud with one toggle and a way back — the harness-as-ownable-layer thesis expressed as a settings switch. Meta pushed from the other side with Muse Code and a genuinely novel commercial move: the same model at two prices, $1.25/$4.25 per million input/output tokens with your data excluded from training, or $0.10/$0.20 with it included — a roughly 12× discount that undercuts DeepSeek-V4-Flash and discounted GPT-5.6 Luna alike, and that a developer accepts by typing a different model name rather than signing anything. Public repositories only show polished code; a working coding harness records the reasoning, the mistakes and the repairs, which is the scarce commodity being bought. The contributor tier's 100-requests-per-minute cap against 3,000 for standard points it at individuals and small teams. The harness itself is worth reading independently: session-persistent subagents editing in parallel inside isolated worktrees, a local log of every model call and file edit so a crashed agent resumes rather than restarts, and /plan, /grill and /goal as shipped defaults.

The newest addition (Aug 2) is a design-pattern survey rather than a tool: Isaac Flath catalogued eight ways AI products resolve ambiguous requests — the recurring product problem that users have different preferences and the right context is hard to extract from them. Products that know their user (a repo, a workspace) can assume context; general assistants like ChatGPT cannot, and must get it from somewhere — asking, memory, defaults, or letting a bad trace teach the product what context was missing. It complements this page's memory/configuration thread from the product-design side: CLAUDE.md-style configuration is one instance of a broader family of context-acquisition patterns.

Before that, the newest token-economics datapoint (July 30) is Token Saver, an open-source MCP extension built at MarkTechPost that uses local hybrid RAG — BM25 over SQLite FTS5 (weighted 0.4) blended with a local all-MiniLM-L6-v2 embedding (0.6) — to stop re-paying for whole PDFs on every conversational turn: the document never leaves the machine and Claude receives only the passages that answer the question, with page numbers attached. On a 233-page filing it cut 133,349 tokens to 740 — 99.4% — packaged as a single .mcpb file with no Python or terminal required, MIT licensed.

Before that (July 29) came Moonshot AI's Kimi K3 — an open-weight, native multimodal agentic model and Moonshot's most capable release to date — landing on Ollama's cloud and dropping directly into coding-agent harnesses via a single launch command (ollama launch claude --model kimi-k3:cloud for Claude Code, with OpenClaw and Hermes also supported); access currently requires a Pro or Max Ollama subscription while Ollama adds capacity. It extends the same one-ollama launch-away pattern already tracked below for Kimi K2.7 Code and GLM-5.2 — model choice inside the harness keeps widening at the same pace as the harnesses themselves.

Before that (July 28), Perplexity brought search into the terminal — a CLI-native surface for its search product rather than a browser-first one, continuing this page's running theme of tools built for where practitioners (and increasingly agents) already work rather than a GUI-first surface; further technical detail was not available in the digest that reported it.

Before that, two July 20 releases widen the DevEx picture from coding agents into adjacent data and model-selection tooling. YC-backed Feyn AI released SQRL, a family of open text-to-SQL models that inspect a live database before writing a query — sampling the actual data to resolve ambiguity instead of guessing from the schema — reaching 70.6% execution accuracy on BIRD Dev; a concrete instance of a tool that treats "read the data first" as a first-class step rather than an afterthought. The same day, MarkTechPost published a roundup of the best local LLMs (comparing Qwen, Gemma, Mistral, and DeepSeek builds) that fit on a single 24GB consumer GPU in 2026 — a practical reference for the on-device/local-first thread this page and Model releases keep tracking.

The newest DevEx signals before that (mid-July) land on the coding-agent front: Mistral shipped Vibe for Code, a coding agent on Devstral 2 pitched as up to 7× more cost-efficient than Claude Sonnet on real-world tasks and benchmarked head-to-head against Claude Code, Cursor, and Codex on one shared scaffold (methodology on the Evals page), while OpenAI's Hayden Bleasel released Blume, a zero-config framework that turns a plain Markdown folder into an AI-ready Astro docs site — documentation as machine-readable output agents can consume, not just render for humans. Both extend the period's larger arc.

Two earlier DevEx signals still frame the framework question, pulling in opposite directions. On one side, Vercel's open-source Eve (June 17) argues the agent abstraction should be radically lighter: an agent is a directory of files, not a class/graph/config, and the framework compiles the directory into durable workflows with channels auto-wired (Slack out of the box) — so an agent becomes a versionable, diffable, one-command-deployable filesystem artifact (the lowest-cognitive-overhead build option, open source via the eve npm package; agent-side framing on the Agents page). On the other, Perplexity's Brain (June 18) is the productized form of the memory substrate practitioners have been hand-building: a context graph of the agent's work that self-synthesizes overnight into an LLM wiki future runs consume, turning "memory hygiene" from a thing you engineer into a managed feature you buy. Both reinforce the period's larger arc — the newest DevEx shift is upward: beyond extending a single agent (skills, MCPs, plugins), teams now manage fleets of agents, and Databricks' open-source Omnigent (June 13, Apache 2.0) is the first serious build-vs-buy answer at that tier — a meta-harness above Claude Code, Codex, and Pi that centralizes access control, audit logs, and cost caps and lets teams publish/share agent configs, collapsing the config drift and duplicate-permission sprawl of running several coding agents (agent-side framing on the Agents page).

Underneath, developer experience continues consolidating around a handful of patterns: CLAUDE.md / project memory files as the standard onboarding artifact for an agent, skills as reusable workflows, MCPs for non-trivial integrations, and Claude Code (with its hooks/skills/remote-control) as the most-cited reference implementation. A sharper version of that consolidation surfaced June 9: the agentic harness — the scaffolding of tools, skills, memory, sandbox, and permissions wrapped around a model — is being framed as a commoditizing layer hardening into a few batteries-included frameworks, just as base LLMs did. Anthropic's Claude Managed Agents (public beta, with Claude Fable 5) is the managed expression of that shift. A sharper version of the same dynamic surfaced July 8 in a practitioner conversation about AMP (a coding-agent harness): as models jump from Opus 4.8 to Fable they absorb harness features outright — once compaction improved, AMP could delete its handoff feature — so the durable test for harness code becomes whether it helps inspect, verify, recover, or merge model work rather than babysit yesterday's model. The plumbing is now being formalized further: xAI's Grok Build shipped a plugin package manager that bundles skills, slash commands, agents, hooks, MCP servers, and LSPs into one installable unit — the most ambitious attempt yet to give a coding agent an extensibility layer at the infrastructure tier, where rivals (Claude Code, Cursor, Copilot) have integrations but no single package manager of comparable surface area. Model choice inside these harnesses keeps widening too: Moonshot's Kimi K2.7 Code (256K context, vision, ~30% fewer thinking tokens) is now one ollama launch away inside Claude Code, Codex, OpenCode, and Cline.

The current practitioner focus is shifting from "how to wire it up" to "how to make it cheap, durable, and grounded" (Eugene Yan's workflow, Parlance Labs on skills-vs-MCPs, boringbot's token-savings findings, Decoding AI's GraphRAG series), and a parallel open-source wave is filling in the surrounding stack: agent firewalls (Deno Claw Patrol), Rust-based GitHub alternatives (Gitdot), unified graph+vector+search databases (HelixDB), document-native UI components (Extend UI), and GUI onboarding for open agent stacks (Nous Hermes Profile Builder). Agent-readable tool packaging, agent-authored low-level code, plugin package managers, and an open-source agent-infra ecosystem now sit alongside cost optimisation and knowledge-graph hygiene as DevEx concerns. The local dev environment is consolidating too: Apple open-sourced Container (Apache 2.0), a Swift-native tool that runs Linux containers as lightweight per-container VMs on Apple Silicon with a Docker-compatible CLI — a first-party answer to the Docker-Desktop-on-ARM friction on what is now the dominant developer machine. AI-assisted app builders are maturing past greenfield-only, too: Google AI Studio's Build mode can now import an existing GitHub repo and turn it into a runtime-compatible, deployable app, making "vibe coding" usable on real codebases rather than only weekend prototypes. On the pedagogy side, the practitioner canon is consolidating in parallel with the tooling: Simon Willison's evolving Agentic Engineering Patterns guide (surfaced Jul 11 via codenewsletter.ai) is emerging as a plain-English reference for the same period's ideas — its "How coding agents work" chapter frames a coding agent as a harness that wraps an LLM with invisible prompts and callable tools (the most powerful being code-execution tools like Bash() and Python()), and its pattern chapters (red/green TDD, linear walkthroughs, "writing code is cheap now") give the harness-and-workflow thread a shared vocabulary for newcomers rather than a new product.

Memory & configuration patterns

Per-project CLAUDE.md, per-repo conventions, and a global ~/.claude/CLAUDE.md for personal preferences is now a documented pattern. Lazy-loading guides (rather than @import) is recommended to keep the always-on context small. The product-design generalization of this thread (Isaac Flath, Aug 2): configuration files are one of roughly eight patterns AI products use to resolve ambiguous requests — alongside asking clarifying questions, persistent memory, sensible defaults, and mining bad traces for the context that was missing. Coding tools have it easiest (the repo is context); general-purpose assistants have to earn the same context explicitly.

Skills vs MCPs vs custom tools

Skills are the lightweight default for a recurring workflow. MCPs are preferred when the extension needs to handle nuanced problems the skill abstraction can't. CLIs and custom tools remain valid for deterministic, distribution-friendly tasks.

Token economics & prompt caching

Standard prompt caching alone yields only modest savings. Structural techniques — keeping cacheable prefixes stable across turns, ordering context from least- to most-volatile, and avoiding mid-prompt edits that invalidate the cache — are what separate the teams seeing ~90% token reductions from those seeing 20–30%. The lesson generalises: write prompts as if they will be cached, not patched. Token Saver (July 30) turns the retrieval-instead-of-resend idea into an installable artifact: a local MCP server doing hybrid BM25+embedding retrieval over PDFs so Claude sees only answering passages (with page numbers) rather than the full document re-sent every turn — 133,349 tokens down to 740 on a 233-page filing, one MIT-licensed .mcpb file. Two September results sharpen the same arithmetic from opposite ends. Spotify's shunt reports ~90% fewer Claude Code tokens in Java testing by routing bulk reads and predictable generation to Gemini 2.5 Flash — the model-mix version of the retrieval-instead-of-resend idea, and one that trades 10 to 30 seconds of latency per handoff for the saving. Against that, the Claude Code changelog records tool definitions being re-rendered after OAuth token refreshes, forcing a full prompt-cache miss roughly hourly: a leak invisible in any single session and expensive in a long one. The two together restate the section's rule with a corollary — write prompts as if they will be cached, and check that nothing in the harness is quietly invalidating the cache on a timer.

Knowledge graphs & agent memory hygiene

For agents backed by GraphRAG-style memory, the failure mode that keeps appearing is not retrieval but identity: how the system decides when two mentions refer to the same entity. Naming similarity is not identity — "Apple" (company) and "apple" (fruit) trivially break a graph if merged on string match, and the harder cases (same name, different people; different aliases, same person) are where most graphs accumulate silent corruption. The emerging guidance is to merge on multi-signal evidence (type, surrounding relationships, source provenance) rather than string distance, treat ontology as something you grow from data rather than design upfront, and keep an unresolved-mentions queue rather than forcing premature merges. A productized counterpoint arrived with Perplexity's Brain (June 18): rather than expose the graph for hand-curation, it builds a context graph of the agent's work and self-synthesizes it overnight into an LLM wiki future runs consume — moving memory from an engineering burden to a managed feature, but inheriting the same identity/corruption risk a self-maintained graph carries (agent-side detail on the Agents → Agent memory section). The build-vs-buy choice now extends to the memory layer, not just the harness.

Agent-native tooling

A distinct emerging pattern is shipping developer tools designed for AI agents as primary users, not just humans. Google's Colab CLI bridges local terminals and remote Colab runtimes — provisioning GPUs/TPUs, running scripts remotely, recovering artifacts — and ships with a prepackaged Colab skill file so agents have built-in context on how to use it (e.g. Antigravity can QLoRA-fine-tune Gemma 3-1B on a Colab GPU in one terminal command). The skill-file-as-tool-documentation convention turns "can a human read the README" into "does the agent ship with the tool's usage baked in." Separately, agents are now authoring performance-critical low-level code: RightNow AI's Autokernel writes a single CUDA kernel and self-tunes it past NVIDIA's own libraries (reportedly up to 14× on some internal kernels), a sign that agent-generated systems code is moving from demo to production.

The same "agents are primary readers" logic is reaching documentation: OpenAI's Hayden Bleasel shipped Blume (July, on npm), a zero-config framework that compiles a plain Markdown folder into an AI-ready Astro docs site, so docs become structured, machine-readable output an agent or LLM can consume rather than a page rendered only for humans — the right default when documentation doubles as a retrieval surface. In the same vein of meeting practitioners where they already work, Perplexity shipped a terminal-native search tool (July 28), putting its search product directly into the command line rather than requiring a browser tab. The most useful additions since are the ones that hand an agent a deterministic artifact instead of asking it to reconstruct one. ripwire (Sep 8) builds an offline code map ranking symbols, dependencies, churn, complexity and likely tests before the agent opens a file — no embeddings, no index server, so the map is reproducible and cheap. Firecrawl's anydoc (Aug 28) added an OCR path to its Markdown conversion at a 190ms median per scanned page and sub-5ms for documents that need no OCR, free and without an API key, which puts a floor under what document ingestion should cost in a pipeline — compare Reducto r-1 at a cent a page for the documents OCR cannot handle at all. Vercel's Run SDK (Aug 26) covers the execution end: untrusted JavaScript or type-stripped TypeScript in a fresh QuickJS context on a worker thread, with only selected operations exposed through hostFunctions and every call crossing by serialization, so existing service clients sit behind the boundary rather than inside it.

And Google's Accelerator Agents (Sep 8) apply the pattern to accelerator work itself — MaxCode converting PyTorch models to JAX, MaxKernel writing, porting, profiling and debugging Pallas kernels. Two August releases move the agent-native line from what the agent can call to what it wakes up inside. Cursor Builds (Aug 14) keeps development environments continuously prepared in the background so a cloud agent starts ready rather than spending its first minutes provisioning, reporting up to 3x faster responses at no extra charge and falling back to the last successful build when one fails, so work continues while a developer debugs. Claude in Chrome (Aug 13) makes the browser side panel a full Cowork session rather than a reduced assistant, with conversations saved to the account and resumable across desktop, web and mobile and existing skills and connectors available without separate setup.

Both attack the same tax: the per-surface, per-session setup cost that made agent tooling feel like several products rather than one, and that shows up as latency in the first case and as lost context in the second. A different kind of agent-native artifact arrived on Sep 10 with ZeroModels, a collection of pretrained models written entirely in Keras 3 — image classification, object detection, segmentation, monocular depth, feature extraction, vision-language and speech recognition — where the same code runs on JAX, PyTorch or TensorFlow and neither transformers nor torch is required at runtime. The relevance here is dependency rather than capability: teams routinely pin a serving image to one framework because a single checkpoint's loader demanded it, and this makes the backend a deployment decision instead of a property inherited from whichever model was chosen first.

Plugin & extensibility layers for coding agents

Beyond ad-hoc skills and MCP servers, coding agents are gaining formal package management, and Sep 11 supplied the first substantial vendor bundle written to a cross-harness spec rather than to one client. Google's Cloud Developer plugin packages its cloud expertise, live documentation and guardrails so an agent can handle authentication, permissions, projects and gcloud safely, and because it targets the open Agent Plugins specification the same artifact loads into Antigravity, Claude Code and Codex without a per-harness port — which is the specification doing the job it was written for. Google Maps published skills the same week on the identical pattern, covering places, geocoding, routing, Street View, air quality and weather. Both share a design decision worth isolating: the skill retrieves current documentation at generation time instead of relying on whatever API surface the model absorbed during training, which turns a plugin from a capability grant into a freshness mechanism.

Alibaba's open-sourced Open Code Review is the counterexample in distribution terms — a CLI rather than a plugin, but one with two years and millions of identified defects behind it. xAI's Grok Build introduced a plugin system where a single plugin bundles skills, slash commands, agents, hooks, MCP servers, and LSPs into one installable unit, browsed and updated from the Grok Build CLI (grok install). Launch-partner plugins span MongoDB, Vercel, Sentry, Cloudflare, Chrome DevTools, and custom-workflow bundles. While every major coding agent (Claude Code, Cursor, Copilot) has integrations, the distinguishing claim is a package manager with this combined surface area — skills, agents, LSPs, and MCP — at the infrastructure layer, turning agent extensibility into something installed and versioned rather than hand-wired. Microsoft's Agent Lightning v1.0.1 (Aug 25) uses that same plugin surface for a different purpose: it installs as a skill inside Claude Code, Codex, Copilot or any other harness, and given an editable agent plus a benchmark it reworks prompts, tools, workflows, model choice and reasoning settings against scored results. The entry price is the eval, which is also the point — it is the only way to find out whether last week's prompt edit helped, and it puts Skill Doctor and AutoSaddler in a line of tools that all convert something measurable into instruction edits. The hazard is the one this page keeps returning to: a harness tuned against a benchmark optimizes that benchmark, and the score collapses on the harder agent index show exactly how far that can travel.

Anthropic's Claude Mods (Sep 15) adds the same layer to its own harness and, in doing so, changes what an extensibility surface is for. The developer-facing half is conventional and deliberately unambitious — plain TypeScript functions that alter how Claude Code looks and behaves, with examples running from hiding sensitive values during a screen share to tracking token usage to running a game above the prompt — and it ships behind an environment flag. The administrative half is the new thing: an admin can disable risky capabilities across an entire organisation, which is an enforcement point rather than a recommendation. Every extension mechanism catalogued above answers the question of what can be added to a harness; this is the first inside a vendor's own agent that answers what can be centrally taken away, and that asymmetry matters because a per-user configuration file is advisory by construction — anyone who can edit it can edit it back. Read against npx geiger-scan, which exists to tell you which installed extensions can already reach your filesystem and credentials, the two are the audit and the control for the same problem, and the control arriving second is the usual order in this industry.

Model selection inside coding agents

The harness is increasingly model-agnostic: a growing list of models drops into Claude Code, Codex, OpenCode, and Cline through a single launch command. The newest addition is Moonshot AI's flagship Kimi K3 (July 29) — an open-weight, native multimodal agentic model, described as Moonshot's most capable to date — now available on Ollama's cloud and launchable straight into Claude Code (ollama launch claude --model kimi-k3:cloud) as well as OpenClaw and Hermes; access currently requires a Pro or Max Ollama subscription while Ollama scales up capacity. It sits alongside earlier additions: Moonshot's Kimi K2.7 Code on Ollama's US-hosted cloud (NVIDIA B300, private/non-trained data; ~30% fewer thinking tokens, 256K context with vision) and Z.ai's GLM-5.2 (MIT-licensed; usable 1M-token context, two thinking-effort levels), which as of June 17 is live on Ollama's US-hosted cloud (NVIDIA Blackwell GPUs, zero-data-retention) and launchable into Claude Code, the Codex App, Hermes, and OpenClaw with one ollama launch glm-5.2:cloud — useful inside a harness for long-horizon, document-heavy coding without switching models. The practical effect for DevEx: switching the underlying coding model is becoming a one-line config change rather than a re-platforming exercise, and open models now reach Western harnesses through US-hosted endpoints without self-hosting. (Model detail on the Model releases page.) The local end of that selection problem got noticeably easier on Sep 9. Rapid-MLX serves a 4-bit Qwen3.5-4B at 61 tokens per second using roughly 6 GB on a base M4 Mac mini — leaving about 10 GB free on a 16 GB machine — and exposes it behind an OpenAI-compatible API, so Cursor, Claude Code and Aider can be pointed at it without any change to the tool.

Its recipe command inspects the machine and recommends the strongest model that fits alongside a faster alternative, which removes the step that usually stops people: not running a local model, but knowing which one their hardware can actually hold while the rest of their environment is open. Combined with Unsloth's Dynamic 3.0 quantization gains at small sizes, the practical question shifts from whether a local model is usable to which tasks are worth routing to it — the same routing logic Uber applied to its own agent bill, at one machine's scale.

Two Sep 14 arrivals extend model-agnosticism to the last surfaces that could plausibly have resisted it. Xcode 27 ships coding agents driven by any model rather than a bundled one, alongside a Device Hub and customisable agent configuration — Apple's first-party IDE declining to lock its assistant to a single vendor, which leaves the harness and the platform integration as what it is actually selling. The same day, code found in the new Siri architecture showed Apple had built the equivalent swap into the assistant itself: Model Delegation registers Claude as a Siri extension exactly as ChatGPT already is, and an inference-provider option can replace Apple's own server-side model. Between them they close the argument this section has been making since the harness commoditised. A tool's differentiation is no longer which model it ships with, because it does not ship with one; it is the integration surface — the documentation it fetches live, the devices it can reach, the permissions it enforces, the review it puts in front of you. Spotify's Portal routing, recorded on the Infrastructure page, is the same insight applied to cost rather than capability: once the model is a parameter, choosing a cheaper one per task is a configuration decision rather than a migration.

The day after, Apple published the developer-facing version and settled what the Siri finding could only imply. iOS 27's upgraded Foundation Models framework (Sep 15) exposes any language model through a single Swift API — Apple's own third-generation on-device models, or cloud models including Claude and Gemini, chosen at the call site — while Siri gains App Intents to reach into applications and take actions, and ships as its own app for the first time. Model Delegation was code found in a shipping binary and could have been a private arrangement between Apple and two labs; a documented framework is the interface every third-party application is expected to build against. So the swap now runs the full height of the platform: the IDE does not bundle a model, the assistant does not bundle a model, and the app API treats the choice as a parameter. What Apple keeps is the same thing it kept in the Siri architecture — the on-device capabilities, the permission model and the intent system — which is the integration surface this section has argued is the actual product, now stated by the platform owner rather than inferred from its behaviour.

The cheapest available instance of the same principle appeared the same day and takes about a minute to apply. Claude Code spawns subagents constantly and each inherits the session model by default, so a Fable 5.1 session pays frontier rates for subagent work that mostly does not need frontier reasoning; setting CLAUDE_CODE_SUBAGENT_MODEL=opus in the environment, or under env in .claude/settings.json, routes them elsewhere while the main conversation stays put. It sets a default only for subagents with no pinned model, and the full resolution order is documented separately — a caveat worth reading before assuming it applies everywhere. The reason it belongs in this section rather than in a tips list is that it is the routing argument at its smallest scale: Spotify cut routine token spend roughly 90% by sending file reads to a cheaper model, Uber applied the same logic to its agent bill, and this is one developer doing it to their own with one line. In each case the enabling condition is identical, which is that nothing above the model had to change.

Open-source agent infrastructure

A wave of open-source projects is filling in the stack around agents rather than the agents themselves. Notable recent drops: Deno's Claw Patrol (MIT) — a firewall between agents and production that parses wire traffic and gates actions (see Safety & policy); Gitdot — a fully open-source, self-hostable GitHub alternative written in Rust; HelixDB — a YC-backed single-engine OLTP database combining graph, vector, and full-text on object storage (Rust), pitched as "one database for everything an AI app needs"; Extend AI's Extend UI — open-source React components for document-native AI apps (PDF/DOCX/XLSX viewers, bounding-box citations, e-signing); and Nous Research's Hermes Profile Builder — a GUI flow to configure identity, model, skills, and MCP servers for the Hermes Agent without the CLI. The throughline: the surrounding infrastructure (security, source hosting, data, UI, onboarding) is increasingly open and agent-shaped.

Two Sep 15 releases add the agent itself back to that list, from opposite ends of the purpose spectrum. Hugging Face's Tau is a terminal coding agent that reads files, edits code, runs commands and keeps a durable session history while streaming what it does — and its stated goal is to be a teaching project, built so the shape of a coding-agent system can be understood without starting from a production codebase, with OpenAI-compatible endpoint support so it can be pointed at whatever model the reader already has. This section has recorded minimal harnesses before, but hip-agent's 200 lines and Headlong's Bash were existence proofs about how little scaffolding a working agent needs; Tau optimises for legibility instead, which is a different target and probably the more useful one for anyone who has to maintain a harness rather than admire one. Cline Desktop comes at it from the deployment end: an open-source application built around open-weight models that runs agents in parallel and automates recurring tasks. Cline has appeared on this page for a year as one of the harnesses a model drops into; shipping it as a product with open weights as the assumed backend rather than the fallback inverts that, and read with Rapid-MLX's local serving it closes a question that has been open all month. Whether a local open-weight model is usable inside a coding agent is settled; which interface you run it from is now the live one.

The agentic harness: build vs buy

The harness is now discussed as a discrete, standardizable component rather than per-project glue. A Decoding AI Magazine teardown breaks it into its parts — tools, skills, memory, sandbox, and permissions — and argues that, like base LLMs before it, the harness is commoditizing into a handful of batteries-included frameworks; once that happens, differentiation moves up to model choice, context engineering, and memory. The framework tier itself is competing on ergonomics: Vercel's open-source Eve (June 17) pushes the abstraction to its minimum — an agent is a directory of files that the framework compiles into durable workflows with channel auth wired automatically — so build-vs-buy at the single-agent layer is no longer "graphs and chains vs a managed service" but increasingly "a few files in a repo vs a managed service." On the "buy" side, Anthropic's Claude Managed Agents (public beta) provides a managed long-running-agent harness with built-in fallback that pairs with Claude Fable 5 out of the box.

And a tier above the single harness, Databricks' open-source Omnigent (Apache 2.0) gives the "manage several agents at once" answer — composing Claude Code, Codex, and Pi under one governance surface (access control, audit logs, cost caps, shareable configs) rather than hand-wiring cross-agent permissions and visibility. The practical takeaway for DevEx: hand-rolled loops increasingly compete against managed offerings at both the single-harness and multi-agent-orchestration tiers, so the question shifts from "how do I build the loop" to "which parts are worth owning." A July 8 practitioner conversation (Vanishing Gradients, on the AMP harness) sharpened the point from the other direction: as the underlying model improves (Opus 4.8 → Fable), it absorbs harness features outright — once compaction got good enough, AMP deleted its handoff feature because the model no longer lost the plot on long threads — so the durable test for any harness code is whether it helps inspect, verify, recover, or merge the model's work, not whether it babysits yesterday's model. (Agent-side framing on the Agents page.) For the plain-English grounding of what a harness actually is, Simon Willison's "How coding agents work" (part of his Agentic Engineering Patterns guide) is the clearest reference: a coding agent is software that wraps an LLM with invisible prompts and callable tools, the most powerful of which run code (a Bash() or Python() tool). The buy side keeps getting cheaper.

Meta shipped Muse Code (Sep 1), a terminal and CI coding agent with approvals and an OS sandbox on by default, and made Muse Spark available through both the Meta Model API and the agent; Z.ai's ZCode covers the same job from the desktop with parallel task execution, scheduled recurring work and mobile control of a run on macOS, Windows or Linux. Sandbox-on-by-default is now the shipping configuration rather than the hardened one, which is a real change from a year ago. Alongside them, GitHub Agentic Workflows (Aug 31) removes the hosting question for a large class of work: agents run from the same events and schedules that already drive CI, under the same permissions, with Copilot, Claude Code, Gemini or Codex as the engine. That leaves the build case narrower than it was — it is now mostly about the loop being unusual (see Headlong), not about the infrastructure being missing. The buy side keeps widening in a specific direction: vendors are absorbing the surrounding development platform, not just the loop.

Cursor Review (Aug 12) — Origin under a new name, apparently heading beyond its closed partner beta — pairs a Codebase tab for syncing and managing GitHub-sourced repositories with an automated pull-request pipeline that escalates to a human only when judgment is needed. Buying a harness increasingly means buying a code host too, which moves the build-vs-buy question from “can we assemble this loop” to a much stickier one about where the repository lives. That is a harder decision to reverse than a harness swap, and it is worth separating the two before treating them as one purchase.

Working when the agent writes the code

The section's open question — if agents write the code, what exactly is the human doing? — got its first answer with numbers attached on Sep 11. Gergely Orosz reports that the strategy actually working is review triaged by blast radius: decide up front which surfaces a human must see, and let everything else clear on linting, type checks, tests and post-deploy monitoring. Duckbill Group's five-engineer team drew that line at auth, public APIs, database schema, design systems and agent skills, went from 60 stalled PRs to 154 merges a week against a prior 80, and cut low-risk merge time from 26 hours to about one. OpenAI and Anthropic operate the same split. This sharpens rather than contradicts Liguori's argument below: her point is that the work moves from writing code to specifying and supervising it, and blast-radius review is what supervision looks like once it has to scale — attention allocated by consequence rather than spread evenly. The measurement caveat is unavoidable and worth stating plainly: merges per week is a throughput number, and no one has published what the defect rate on the unreviewed path looks like six months on. The tooling followed the same logic this week. A Codex flag, experimental_mode under [features.context_management], swaps end-of-session compaction for notes the model writes and later searches, because what compaction destroys is not the decision but the reasoning that justified it — precisely the material a human supervising a long refactor needs to review against.

And npx geiger-scan answers the adjacent question nobody had been asking: which of the agents, MCP servers, hooks and extensions already installed can execute code, read your filesystem or reach your credentials. Clare Liguori, a senior principal engineer at AWS, argues in a ten-principle guide she calls frontier engineering that nearly every team now has coding agents and almost none ship faster, because the split that matters is between developers who changed their tools and developers who changed their work — the second group builds the agentic system that builds the software and writes under 1% of shipped code by hand. Her principles compress to three: write intent rather than code, specifying roles, edge cases, acceptance criteria and how to test the failure path, then review output against that spec; make the environment do the supervising, with fast local test loops, docs written to be read by machines, and tight permission boundaries; and delegate broadly while discarding output that misses instead of repairing it. Lauren Tan's pstack part 2 gives the same argument a unit of work.

Against the current fashion for elaborate plan documents — progress-shaped rather than progress, in her phrasing — she argues for small changes you have actually verified and are willing to throw away, which follows directly from part 1's focus on verification: if confirming a change is the expensive step, the changes have to stay small enough that confirmation stays cheap and being wrong stays survivable. Both are candid about the cost. Liguori's is explicit that the first weeks feel slower and the payoff arrives as the deferred re-architecture and the missing tests becoming affordable, which is the honest version of a claim usually made as a productivity multiple.

Two September items give the supervision argument something firmer than throughput to stand on. Simon Willison and Alex Garcia shipped Datasette 1.0a39 and 0.65.4 (Sep 11) as security releases after auditing the codebase with Claude Fable 5.1, GPT-5.6 and GPT-6 Astra, and the honest accounting is in the ratio: the models found genuinely subtle bugs, and fixing what they found took almost a week of two people collaborating in a private repository. Their working split is the transferable part — for most issues one person wrote the automated test that demonstrated the bug and the other implemented the fix, so two humans had eyes on every issue and the coding agents driving them ran different models. That is blast-radius review generalised past code review into an audit: the expensive human step is not reading the diff but constructing the evidence that the bug is real, and splitting it across two people keeps one agent's confident summary from becoming the only account of what happened. Willison says frontier-model security audits are now permanently part of their process, which is the first time an established open-source maintainer has committed to that publicly rather than reporting a one-off. Beside it, a much smaller change makes the same point ergonomically: Claude Code's /diff panel (v2.1.260 and later, after /tui fullscreen, terminal at least 110 columns) puts uncommitted changes beside the conversation and refreshes them as the agent edits, so the choice stops being between trusting the summary and leaving the session to go and look.

The starkest consequence of cheap generated code this cycle is an architecture decision running backwards. Shopify is moving its mobile apps off React Native (Sep 10) and back to separate Swift and Kotlin codebases after six years, and the post is unusually fair to what it is leaving: the 2020 reasons — stop building every feature twice, let developers work across the stack, spend less time chasing parity — all still describe real costs of going native, and none of them has disappeared. What changed is that agents now absorb enough of the implementation, translation, testing and review work that duplication is no longer the deciding factor. Every abstraction argument in this industry has assumed that writing the same thing twice is the expensive part; if that cost collapses, a whole class of unifying layers loses its justification while the platform-specific ones become affordable again. Shopify is also the maintainer of react-native-skia, flash-list and restyle, two of which are now being rehomed — so the second-order effect is that a decision made about agent economics inside one company reallocates maintenance for an ecosystem outside it. It is worth reading next to the blast-radius numbers above: both are cases of agent capability changing not how fast a team works but which shape of work it chooses.

The section's central number got a third claimant on Sep 15, and the honest thing to say about it is that the set still has no independent member. Addy Osmani, speaking for Anthropic, says Claude now writes roughly 80% of the company's production code and that the team ships about eight times more as a result. It is a vendor measuring its own product, with no published definition of production code or of a shipped unit and no defect rate attached, which puts it in exactly the position Liguori's under-1%-by-hand figure and Duckbill's 154-merges-a-week already occupy: three organisations reporting large effects, none externally audited, and no one publishing what the unreviewed path looks like six months on. What makes the Anthropic figure worth recording anyway is its form. A share is falsifiable in a way a productivity multiple is not — 80% of authored lines is a thing a company could in principle be shown to be wrong about, whereas “eight times more” depends entirely on what is being counted. The cost side of the same question got a genuinely measured answer the same day, from a tool rather than a testimonial: Alibaba reports Open Code Review using about one-ninth the tokens of a general-purpose agent on the same review, achieved by hard-coding the review steps that need no judgement and leaving the rest to the LLM agent. That is the hybrid design this page has watched several teams attempt, with the saving denominated in tokens instead of asserted in prose, and it suggests the durable gains in this section will come from deciding which parts of a workflow do not need a model at all.

Multi-session and parallel work

Running 3–6 sessions in parallel (via tmux + git worktrees) is becoming the practitioner default. The bottleneck shifts from execution to writing clear specs and reviewing outputs. The unsolved part has been that the sessions belong to different vendors: a developer paying for Claude Code, Codex and Cursor can drive one at a time, and the accumulated context that justified all three subscriptions is stranded inside whichever client produced it. Traycer (Sep 10) is the first product to sell the seam itself — one workspace running Claude Code, Codex, OpenCode and Cursor side by side, work handed from one chat to another, and context, artifacts and history kept in a single place rather than per-tool. Whether a neutral workspace can hold state that every vendor is simultaneously building its own client to own is a business question rather than a technical one, and it is the same question the harness-as-a-runtime services are betting the other way on.
