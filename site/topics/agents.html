Agents & agentic systems

Last updated: 2026-09-21

Current state

Today’s cycle’s clearest result is also its smallest intervention. Meta AI’s Proactive Memory Agent runs a second model beside the action agent, keeps notes from its eight most recent outputs — facts, environment details, fixes that worked, commands that failed — and at each step injects either nothing or one short reminder. On Terminal-Bench 2.0 that moved Claude Sonnet 4.5 from 37.6% to 45.9% and Opus 4.6 from 43.5% to 45.9%; on τ2-Bench, Sonnet from 55.0% to 61.8%. The control is what makes it a finding rather than a prompting trick: reminding at every step did worse than letting the memory agent pick the moment, which says the deficit being repaired is attention allocation, not lost context. It needs no retraining, so it bolts onto an existing agent — and the gains shrink on the stronger action model, which is the number to watch if the effect is partly covering for weaker instruction-following.

Two agents shipped this week with opposite answers to the question of whose authority an agent acts under. Google’s family agent gets its own cloud computer and its own Google account, serving up to six people from a household’s shared mail, files and calendars and asking permission before acting outside the group — the permission boundary becomes a property of the account. Meta’s Muse for Mac takes the other route, borrowing the user’s own access to files, mail, messages, calendar and notes, with opt-in scopes, approval gates on deletes and sends, and a secure VM — qualified by the clause that Meta can still reach the data when needed to operate the service. The pairing matters because this week’s OpenAI breach showed exactly what a borrowed identity costs: one hijacked employee session reached the internal monorepo because the agent carried the connectors.

The browser loop got faster and got its boundary in the same week. Browser Use’s jev-ultrafast hands the choice of operation and target to Jev and calls a text model only when something must be typed, finding a Google Flights itinerary in 7.073 seconds across 17 requests at a median 178ms. The premise is that most steps in a browser trajectory are selections among visible options, not judgements about the page — and Context7 measured where that stops holding, with the same model at 27% against 93% on crawl-root selection while running 10–170× faster. Alongside, Agora proposes an append-only Git DAG as the exchange format for research agents, making every hypothesis, result and verification a commit with a parent and a hash. It ships with no throughput or quality numbers, so it offers a provenance argument rather than evidence that agents coordinate better through it.

Earlier cycles

Today's cycle is about the protocol becoming the thing platforms publish rather than the thing agents load. Google opened early access to an MCP server for Google Home, letting an outside agent such as ChatGPT control the whole device ecosystem — gated behind a Google Cloud project and a US Premium Advanced subscription, but a consumer platform exposing its control surface as MCP rather than as a partner integration all the same. Stanford's Paper2Agent does it to the literature, reading a paper with its repository and emitting a tested MCP server: 22 tools for the AlphaGenome agent in about 45 minutes for US $14, and 74 of 100 bioRxiv papers converted. The auditing question changes shape with them. It is no longer which servers an agent has loaded, but what a platform lets any connected agent do — and Google Home answers that with a house.

The counterweight arrives at the tool-call boundary. Agent-net's Webagent (Sep 14, Apache 2.0, v0) turns a website into an agent from one JSON spec with nine pluggable slots, and routes every call through action.Guard before it runs — the permission check as a structural property of the harness rather than a sentence in a prompt. Google's Agent Anomaly Detection (private preview) takes the after-the-fact position instead, watching deployed agents for anomalies in the logs and traces the platform already collects; free at runtime, and blind to whatever the harness did not record. Tencent's BrowserSkill (3.5k stars) shows what gets traded when neither is available: it drives a separate window against the user's already-logged-in browser profile, handing back control for CAPTCHAs, which solves the authentication problem that defeats computer-use agents on real sites by borrowing the user's whole identity for the duration.

The prior cycle was about supervision, and it arrived with the first honest price tag on running agents in bulk. Nous Research refactored Hermes with 1,393 agents for roughly $19,000 in tokens and published the procedure rather than the headline: plan, shard carefully, review every shard, reconcile conflicts, and expect strange breakage when hundreds of workers touch one repository. That last clause names a failure this page has not previously had a case study for — not an agent going wrong, but many agents each being correct about overlapping parts of the same codebase, which neither the channel designs nor the fixed-pipeline designs below reconcile. A circulated Codex pattern supplies the cheap counterpart: Astra orchestrates, Sol and Luna execute, and a 15-minute heartbeat inspects progress mid-run and corrects drift before the workers finish, which is supervision in flight against Foreman's inspection at the end. Cognition's Devin Fusion takes the same instinct into model choice, keeping a frontier model as lead that plans, reviews and can reclaim control, while a cheaper model executes — explicitly not a one-shot router, because a routing decision made before the work starts has no recovery path when it is wrong. None of the three has published the parameter that decides whether it pays: no measured heartbeat interval, no comparative figures for Fusion, and $19K as a floor for swarm work rather than a result.

The prior cycle turned the harness thesis into two pieces of buildable instruction, which is the point at which an argument stops being a position. LangChain's Sydney Runkle published the build order (Sep 15): start bare with create_agent running the loop over a model, a few tools and a prompt; add middleware, defined as everything a prompt cannot do — trimming context before it overruns, retrying failed tools, redacting sensitive data, pausing for human review, capping spend; then fit the harness to the specific task rather than building one generic wrapper. That middle list is the section's own failure catalogue named as a standard layer, which is what converts “the harness is the product” from an observation into an interface with a quickstart behind it. Google Cloud supplied the orchestration half the same day, and its routing rule improves on the one in general use: Gemini 3.8 Flash does routine work, and anything harder or irreversible escalates to Claude Fable 5.1. Cost tiering splits on guessed difficulty; reversibility is a property of the action the harness can read before the call, and it puts the expensive model exactly where a mistake cannot be undone.

If the harness is the product, the prior cycle shows who is buying it and where the seams are. Garry Tan reports that almost every non-hardware startup at Y Combinator's latest demo day is building a domain-specific harness — the tools, files, memory and completion logic wrapped around a model — on the bet that encoding how a job is actually done in one industry survives swapping the model underneath. One investor's read of one batch is not a measurement, but it lines up with what OpenAI, Anthropic and LangChain each shipped this month, and it names the layer the money is moving to. At the consumer end, Apple built the same swap into Siri: Model Delegation lets Claude register as a Siri extension exactly as ChatGPT already does, with the delegated model handing tasks back whenever a request needs an Apple system feature, and a separate inference-provider option can replace Apple's own server-side Siri model entirely. The hand-back boundary is the design worth studying — the third-party model gets the reasoning, the platform keeps everything that touches the device.

The harness stopped being something you assemble and became something you buy. OpenAI's Agents API (Sep 11, public beta) sells the managed scaffolding behind Codex directly: one call launches an agent with its own compute environment, files, tools, MCP servers and up to three concurrent subagents, carrying work across multiple context windows, compacting stale context on its own, discovering tools only when they are needed, and composing tool results in code rather than returning every intermediate result to the model. There is no platform fee — you pay for models and tools — and it runs in OpenAI's sandbox, on your own infrastructure, or via Vercel and Cloudflare. That is the layer this page has spent a year describing as separate from the model, now priced separately from it. Cursor Projects the same day takes the coordinator further up: a persistent agent holding months of context, delegating to thousands of subagents, and starting work from a Slack message, a schedule or a pull request rather than a prompt, with Cursor reporting 30% more merged PRs for new users and six times as many for people who work primarily through it — vendor figures that count merges, not correctness.

The counterweight this cycle is about what a long agent run leaves behind. Simon Willison gave ChatGPT Work with GPT-6 Astra a single sentence — 5K and 10K running loops from his house, using OpenStreetMap — and got back exactly that after 27 minutes: address resolved through Nominatim, roads and trails pulled through Overpass, loops computed locally, results returned as an embedded D3 map plus GPX and GeoJSON. The code that did it was never visible in the UI, and by the time he asked for it the thread had compacted and it was gone. That is a harness defect with a specific fix, which he states plainly: a system that compacts must preserve the pre-compaction text and expose it through a tool call. It sits directly against SelfCompact below, which improved when to compact; nobody has yet made compaction non-destructive to the record of what the agent did, and a 27-minute run whose working cannot be recovered is not a reproducible result.

Two counterweights landed beside them. Google scored thousands of submissions to its agents challenge and found the surviving patterns were unglamorous: bidirectional MCP, event-driven concurrency, validating fallback-model output exactly as strictly as the primary's, and cheap routing ahead of expensive calls, with one team serving over 40% of requests from a zero-token regex layer — the strongest “multi-agent” systems distinguished by engineering rather than by agent count. And SelfCompact (Johns Hopkins and Apple) shows how much of the compaction problem is criteria rather than machinery: a probe firing every 16,000 tokens asks the model to judge its own state against an explicit rubric — compact after a finished sub-task, never mid-step — lifting Qwen3-30B-A3B on IMO-Answerbench to 52.1% against 48.7% for fixed-interval summarisation and 45.2% for none, with no fine-tuning; swap the rubric for a bare “do you want to compact?” and the gain vanishes. AWS's open-source Pizza Bot supplies the missing interface for all of this, treating a background agent's output as an inbox — finished work in Unread, work awaiting approval in Action, on-disk checkpoints so a closed tab does not end a task.

Before this cycle, the gap the extension standard left open got its first managed answer, and one arrival put a governor on the thing agents actually overrun. LangChain's Connections (Sep 10) makes explicit a distinction harnesses have been leaving implicit: an agent-owned secret used on everyone's behalf, appropriate for a web search, against a user-owned OAuth grant borrowed for the duration of one caller's request, appropriate for filing a ticket as the person who asked. Per-caller identity is what makes the second case auditable instead of a shared service account with a name pasted into the prompt. Hugging Face's autonomous ML engineer (Sep 10), running literature research, dataset construction and training through to a published demo from a plain-English brief, is notable for the same reason in a different register: each run gets its own dashboard, and the user sets a compute budget the agent is held to. Long-running agents that train things are the class where cost failure stays silent until the invoice, and treating the budget as part of the task specification rather than as after-the-fact monitoring is the first mainstream attempt to bound it. Both are about authority and limits rather than capability, which is where the portability work stopped.

Agent Plugins 1.0 (Aug 13–14) put native Agent Skills and MCP configuration in one predictable directory and manifest so a plugin built once loads in any compatible client, with client-specific features quarantined in namespaced folders and installation, permissions and trust left to each client — standardising what an agent can do while leaving untouched what it may reach, the same seam the role-confusion account of prompt injection names as the actual failure. Two results the same week move attention from capability to loop design. Foreman runs each task through Classifier, Analyst, Implementer and Reviewer stations and returns a reviewed draft pull request, with the Reviewer judging the real diff from fresh context rather than grading the plan it was handed — the concrete form of the argument that the best verifier is an agent that did not write the code. And a genetic search over agent designs cut a CLI's startup from 142.0ms to 98.6ms with a variant that did not exist when the search began, kept honest by binary gates that discard broken candidates and a numeric rubric frozen before any results appeared. Both substitute measurement for intuition about agent structure, which is the direction the memory strand has been forced in as well: re-running memory-based agents across shuffled task orders shows much of their reported self-improvement is evaluation noise and sequencing rather than learning.

Before that, the consumer agent had arrived with an isolation model attached. Meta's Muse (Sep 9) gives every user a persistent agent with its own cloud computer and browser that keeps running after the app closes, and pairs it with a separate Sentinel agent inspecting everything leaving the VM, hiding passwords from Muse itself and gating sensitive actions behind approval — the egress check sitting outside the agent being checked, which is the whole product. Ben Dicken's case for database-backed memory pushed the other way, toward less machinery: Postgres or SQLite plus views, scoped credentials, result caps and short timeouts already supplies the governance that was the real bottleneck, and agents are already fluent in SQL. A proposed policy algebra put a price on continuous enforcement — 94.8% of rule-breaking actions stopped or corrected, 86.9% of legitimate ones completed — so one legitimate task in eight is what it currently costs.

Standards and incumbents moved on the same axis. The MCP roadmap puts progressive tool discovery and a single tool-result contract at the top of its list — the first fixes the “100 tools in context before anyone asks anything” tax, the second gives client authors one shape to build against — though it is a prioritization document, not a spec. Anthropic folded computer use, browser access, versioned skills and reusable files into one production surface, so a procedure is uploaded once, version-pinned, and reused by file ID; its availability language is inconsistent between the dated announcement and cached docs, so it should be verified per account. Slack Code put agent diffs and live previews inside team channels on every plan, making the incumbent's version of the bet that Switch, AgentConnect and Concord made first. Cursor's cloud agents gained event subscriptions, per-VM subagents and the ability to be steered mid-run without interruption, and OneCLI generalized Vercel Connect's credential model to a whole harness: a sandboxed agent per employee, a gateway that injects credentials so the agent never holds them, an outbound-only runner with no inbound ports. Google Cloud's five long-horizon agent patterns — stable prefixes, background learning, persistent workspaces, explicit failures, guard chains — are the most quietly useful item of the set, because they target the bugs that never raise an error: burnt cache, lost memory, wiped tools, a timed-out sub-agent marked done.

Underneath all of it, the harness is still openly claimed to be the higher-leverage layer. A Y Combinator talk this week argued that improving the scaffolding around a model — tools, memory, integrations — moves reasoning scores further than upgrading the model does, with some harnesses rewriting their own code; that is a claim rather than a measurement, but it lands in the same place as the 99.9%-versus-62.7% ARC-AGI-3 gap that came from harness design rather than weights. Two releases push the opposite way from framework accretion: hip-agent reduces the loop to about 200 lines of Python by making configuration environment variables, actions shell commands and a subagent a child process, and Headlong fits an entire microharness into under 10,000 lines of Bash while inverting the request/response shape — its agent keeps thinking, and messages are observations it may or may not answer. Below the harness, routing moved up a level: AgentSky puts Claude Code, Codex, Hermes, DeepSeek Harness, Kimi Code and opencode behind one API where the agent and the model are chosen in the same request, and Monid does it for tools, 1,700+ of them with the price visible before the agent commits. Alongside them, three projects — SandboxAQ's Switch, AgentConnect and Concord — all bet that agents belong in the team's existing chat rather than in a coordination layer of their own, replacing the current default of writing to a shared file and hoping. On memory, Memoryfields keeps agent state as Markdown files with YAML metadata over a SQLite vector index, and Google's WikiSkill co-evolves reusable skills with a persistent wiki built from past runs; and Browser Use adopted WebMCP, so a cooperating site hands the agent its actions instead of making it recover them from pixels.

Multi-agent tooling caught up with multi-agent ambition last month. Hermes Agent v0.21.0 shipped the plumbing that breaks first when several agents genuinely run together — bot-to-bot messaging across gateways, cron with continuity, JSON schema validation, and, most usefully, live steering of delegated subagents mid-run, which closes the gap left when delegation went asynchronous in June and a parent could dispatch work but not correct it without killing the child. OpenClaw 2.0 added the human counterpart: shared cloud sessions, so a second person can join or take over a live run without losing context — handover having been the unexamined gap in long-running agent work, where state lived in one operator's session.

September adds a genuine disagreement about harness design. A detailed architecture post argues that unavoidable complexity should be absorbed by core abstractions rather than pushed onto extensions and users — close to the opposite of DeepSeek Harness's plugin-everything posture, where models, tools, skills, sessions, sandboxes, storage, loops and scheduling are all swappable. Both ship working systems, so this is a live argument rather than a theoretical one. Alongside it, funes pushes on ownership: a durable memory layer carrying session history across machines and across agents — Claude Code, Codex, pi and Hermes against one local store — on the reasoning that if the harness is commoditizing and the model is rented, accumulated context is the asset a developer actually keeps, and it should not live inside one vendor's session format.

August's two contributions both attack the same constraint from opposite ends — what an agent carries and what it runs inside. On context, Xiaohongshu's Self-GC replaces fixed compaction rules with a planner model that decides per item whether to keep it, fold it into storage with a restorable pointer, mask its repetitive middle, or prune it outright, triggering at 30% context fill and applying a plan only when it saves 30% of tokens. It deliberately removes less than rule-based compaction (43.95% of tokens against 61.90–69.87%) and preserves later-needed detail far more often (84.85% against 54.55–69.70%) — the first quantified statement of the trade every long-running agent makes between cost and forgetting, though the authors measured retention, not output quality. On the harness, DeepSeek open-sourced the scaffolding its own benchmarks ran in (MIT, model-agnostic, plugin kernel), which does more for the harness-commoditization argument below than any essay: DeepSeek-V4-Pro-0813 scores 87.9% on Terminal-Bench 2.1 in DeepSeek Harness's minimal mode, 78.7% on Terminus 2, and 54.68% on Vals AI's — a 33-point spread on one checkpoint, which is the scale of the scaffolding contribution nobody else publishes.

Two July 31 signals push agents toward richer context and a bigger surface. On context: an enterprise-data thread argues most organizations don’t have a model problem, they have a context problem — even the best LLM can’t personalize an experience, detect fraud, or make intelligent recommendations if it doesn’t know what the customer has done, is doing right now, or what matters in the moment — and documents engineering teams wiring real-time behavioral data directly into agents via Snowplow Signals and Google’s Agent Development Kit (ADK), powering Gemini Enterprise agents with practical production architectures. On surface: Perplexity’s Personal Computer is an agentic tool that turns the operating system itself into an AI system, positioning Perplexity’s agent as a "general-purpose digital worker" — the step past terminal-native search in the OS-as-agent-surface progression this page tracks.

A fourth installment in the harness-engineering series landed July 28: Paul Iusztin's "The Bare-Bones Coding Agent Loop" strips the framework down to a minimal reference implementation — one agent loop, nine tools, and a terminal you can steer — designed to make explicit what Claude Code and Codex actually do under the hood rather than leaving their architecture as a black box. The series' third installment (also July 28) came from the other side of the pairing: Hugo Bowne-Anderson's "How to Build an Effective Agent Harness" turns his July 21 pushback into a working framework, mapping agent design along two axes — context complexity and action complexity — and naming the harness's five runtime jobs (run the reasoning loop, execute tools, assemble and manage context, persist state, enforce boundaries), illustrated with Pi, OpenClaw, Codex, and Claude Code as worked examples rather than templates to copy wholesale.

The newest thread before that (mid-to-late July) is "harness engineering" being named and argued over as a discipline in its own right. On July 21, two independent newsletters converged on the same idea from opposite ends: Decoding AI's Paul Iusztin argued that as frontier models commoditize, the harness — not the model — is what a builder actually owns, framing Claude Code, Codex, and Cursor as different harness implementations built on the same rentable frontier models; Vanishing Gradients' Hugo Bowne-Anderson pushed back against the implied prescription, arguing against overengineering the harness and that the right amount of scaffolding depends on an agent's actual action and context complexity rather than a default checklist. Iusztin continued the series July 22 with "Building a Coding Agent From Scratch," walking through designing a harness around the model — from the basic agent loop up to a remote swarm.

NVIDIA entered the same layer from the enterprise-platform side on July 21 with its Agent Toolkit, an open foundation of models, tools, skills, and a secure runtime meant to help enterprises build agents tuned to domain-specific workflows — and on July 19 extended agentic AI into vision, shipping skills such as Multi-View 3D Tracking (MV3DT) that let coding agents (Claude Code, Codex, Cursor) build full video-analytics pipelines from a plain-English prompt. On the product side, Andrew Ng released OpenWorker (July 25), an MIT-licensed, local-first desktop agent that returns finished deliverables — a polished doc, a filled spreadsheet — instead of chat replies, working across 35 app connectors while keeping data on-device; a concrete instance of the on-device/local-agent thread this page has been tracking, and of the harness question above in product form (what does a harness owe the user beyond a chat transcript).

The week's clearest theme before that is that the agent infrastructure layer is being built primitive by primitive — memory, isolation, orchestration, and observability, the four pillars of production-grade agents, all gained new building blocks at once. The most consequential is agent memory that compounds: Perplexity's Brain (June 18, in its Computer product) is the first production memory system that improves an agent's future task performance rather than just recalling user facts — every completed task feeds a context graph that Brain reviews overnight, synthesizing learnings into an auto-generated "LLM wiki" so tomorrow's runs start smarter than today's. That reframes agent memory from "remember the user" to "remember the work," and changes the ROI math for anyone running agents at scale (quality improves with use, without extra prompting). Beneath the productized layer, the open memory-framework field is still an unsettled race — Decoding AI Magazine's July 14 teardown pits Graphiti, mem0, cognee, and HydraDB against each other by building one unified memory on a single database, arguing that nobody has yet "cracked" agent memory and that each framework hides its own trade-offs. Alongside it, framework ergonomics took a notable step down in cognitive overhead with Vercel's open-source Eve (June 17), which treats an agent as just a directory of files — compiled into durable workflows with channel auth wired up automatically — making agents versionable, diffable, and one-command deployable rather than something you express as graphs or chains. Multi-agent parallelism also matured: Nous Research's Hermes async subagents (June 16) let delegated work run in the background without blocking the parent chat, removing the synchronous-delegation bottleneck in open multi-agent workflows.

These sit on top of the prior signal that the agent stack is growing upward, not outward: the contested layer is no longer the model or even the harness, but the layer above them — meta-orchestrators, governance, and multi-model fusion that compose several agents into one controllable system. Databricks' open-source Omnigent (June 13, Apache 2.0) is the clearest instance: a meta-harness that sits one level above coding agents (Claude Code, Codex, Pi, custom) to compose them into workflows, govern them with unified access control / audit logs / cost caps, and share agent configs across teams — addressing the config drift, duplicate permissions, and zero cross-agent visibility every multi-agent shop hits. That it comes from Databricks under Apache 2.0 (rather than a startup) gives it institutional weight, and it fits a broader "investment moving from base layer → control layer" trend alongside OpenRouter's Fusion (multi-model routing) and agent-isolation tooling like Bastion. This reframes the earlier harness-commoditization argument: if the single-agent harness is becoming a commodity component, the new differentiator is the orchestration and governance layer stacked on top of it.

The model/harness ends are still hardening underneath. On June 9 Anthropic released Claude Fable 5, explicitly built for long-horizon autonomy — it runs independently longer than any prior Claude, plans across stages, and verifies its own work — and shipped it with Claude Managed Agents, a managed long-running-agent harness now in public beta, plus an "advisor" pattern where cheap worker models call Fable 5 mid-task to check plans. That product move lands alongside a practitioner argument that the agentic harness itself is commoditizing into a handful of standardized, batteries-included frameworks (tools, skills, memory, sandbox, permissions) — i.e. once the harness is a component, model choice and context engineering become the differentiators. A July 8 practitioner conversation (Vanishing Gradients, on the AMP harness) pushed the same logic further: as models improve from Opus 4.8 to Fable they absorb harness features outright — AMP deleted its handoff feature once compaction got good enough — so harness code survives only if it helps inspect, verify, recover, or merge the model's work (see Tools & DevEx).

Two new threads sharpen how agents are made reliable, not just more capable. Stanford's TRACE turns an agent's recurring failures into training signal — it detects a repeated failure, auto-builds a capability-targeted RL environment around it, and trains a LoRA adapter to fix that exact gap (training detail on the Training & RL page). And a "loop engineering" discipline is being named around the plan → act → verify → repeat loop, arguing that verifiers, persistent state, and well-defined stop conditions — not one-shot prompting — are what separate an autonomous agent from one that runs until it burns the token budget. A parallel clarification effort is underway on agentic search, which practitioners note splinters into three distinct patterns (retrieval-, harness-, and model-centric). At the model layer, large open releases are now explicitly architected for long-horizon agent loops — NVIDIA's Nemotron 3 Ultra (550B/55B-active hybrid Mamba-Transformer MoE) is purpose-built for "complex, long-running agentic workflows," joining Fable 5, Opus 4.8, MiniMax M3, and Qwen3.7-Plus.

Three other currents stand out. First, retrieval is becoming agentic rather than one-shot: Google shipped an Agentic RAG framework into Gemini Enterprise (plan → rewrite → re-search until context is sufficient, +34% factuality, 90.1% cross-corpus accuracy, with a "Sufficient Context Agent" that refuses to answer on incomplete evidence), and Harness-1 is a 20B retrieval subagent trained with RL inside a stateful search harness that decides how and when to search. Second, agents keep moving on-device: alongside OpenJarvis and laptop-class Gemma 4, Kimi Work runs a native agent swarm of up to 300 parallel agents locally. Third, multi-agent orchestration continues maturing as a shippable build pattern (e.g. a six-agent Claude Code team backed by graph memory). The open ecosystem also has competitive browser computer-use agents (Microsoft Fara1.5; Kimi's WebBridge), and the agentic-data-science domain reframing continues — now extending to science with Synthetic Sciences' open-source OpenScience (Apache 2.0), a model-agnostic workbench that runs the full research loop (literature review, experimentation, paper drafting) on the researcher's own infrastructure, the first credible open equivalent of the closed "AI scientist" tools every major lab has built internally. Practitioner debate on extension patterns (MCPs vs CLIs vs skills vs custom tools) continues with no consensus winner.

The enterprise runtime for agents is now valuable enough to consolidate: on June 11 OpenAI agreed to acquire Ona — a platform supplying trusted, customer-controlled cloud environments where agent work persists across devices and lives inside enterprise systems — to fold into Codex, signaling that the secure long-running-agent execution layer is becoming a strategic asset alongside the model and the harness (see Industry & business). Two July 16 releases sharpen both ends of the harness-commoditization argument. On the runtime side, Mistral's Vibe Code Mode joins the Ona/Codex pattern with its own dedicated web surface for remote coding agents: sessions run in parallel, persist while the developer's machine is off, execute in isolated sandboxes, and connect to GitHub through to a pull request, with a new VS Code extension bringing the same agent into the IDE and a CLI /teleport command moving a live session between terminal and cloud while keeping history and approvals intact — evidence that persistent, portable remote execution is becoming a standard feature developers expect from any coding-agent vendor, not an Ona/Codex exclusive. On the harness side itself, SpaceXAI open-sourced Grok Build — the Rust terminal coding agent behind its grok CLI — under Apache 2.0: not the model, but the harness (the full-screen TUI, the agent runtime, and the tool layer for file edits and shell execution), running interactively, headlessly in scripts, or via the Agent Client Protocol. Open-sourcing the harness under a permissive license decouples the agent scaffold from Grok's weights entirely, letting anyone run xAI's exact coding-agent runtime on any model — the clearest evidence yet for the practitioner argument that the harness is hardening into a commodity, shareable component while differentiation moves to the model and the layers stacked on top of it.

Agent memory

Memory is emerging as a distinct, contested pillar of the agent stack, and the axis that matters is what gets remembered. Most agent-memory systems remember the user (preferences, prior conversations) for better recall. Perplexity's Brain (June 18, inside the $200/mo Computer plan) instead remembers the work: a continuously learning context graph captures what the agent did, which sources it used, and which patterns produced good results, then an overnight synthesis pass distills that graph into an auto-generated "LLM wiki" consumed by future runs. The distinction is that Brain is positioned as the first production memory layer that improves agent performance on future tasks rather than just retrieval — so the agent compounds, and the longer it runs the better it gets. This is the user-facing, product counterpart to the graph-memory substrate practitioners have been assembling by hand (see Tools & DevEx → knowledge-graph hygiene); the open question is whether self-synthesized work memory stays accurate over time or accumulates the same silent corruption that plagues hand-built knowledge graphs. One level down from the product, the substrate is still contested: a July 14 Decoding AI Magazine teardown builds a single unified memory across Graphiti (temporal knowledge graph), mem0, cognee, and HydraDB on one database to expose the trade-offs each hides, and concludes that no framework has yet "cracked" agent memory — the retrieval model, the update path, and how aggressively each consolidates facts all differ, so the choice remains an engineering judgment rather than a settled default.

Meta AI’s Proactive Memory Agent (Sep 18) is the first result in this thread to separate having the context from being reminded of it. A second agent watches the action agent’s eight most recent outputs and maintains notes — facts, environment details such as the working directory, fixes that worked, unfinished parts of the problem, commands that failed — then at each step injects either nothing or one short reminder. On Terminal-Bench 2.0 that took Claude Sonnet 4.5 from 37.6% to 45.9%, Opus 4.6 from 43.5% to 45.9%, and a fine-tuned Qwen3.5-27B memory agent lifted Qwen3.5-27B from 37.6% to 41.1%; on τ2-Bench Sonnet went from 55.0% to 61.8%, Opus from 66.2% to 68.7%. The control is what makes it more than a prompting trick: reminding at every step did worse than letting the memory agent choose the moment, which says the failure being fixed is attention allocation rather than context loss. It is also the cheapest form this section tracks — the action model is untouched, so it bolts onto an existing agent and survives swapping the model underneath. The gains are smallest on the strongest action model, which is the pattern to watch if the effect is partly compensating for weaker instruction-following.

The July 31 Snowplow Signals + Google ADK thread extends memory into real-time customer context: rather than just persisting an agent’s own state, production teams are streaming live behavioral data (what the user has done, is doing now) into the agent’s context via a dedicated signals layer — framing enterprise agent quality as a context problem, not a model problem. Two designs from this cycle push in opposite directions on where memory should live. Memoryfields (Sep 1) argues for the filesystem: portable Markdown with optional YAML metadata and a SQLite vector index, so memory is inspectable data rather than a proprietary retrieval pipeline — the same instinct behind funes and Anthropic's editable memory files, where “you can read and edit it” is the primary requirement. Google's WikiSkill (Aug 31) argues for consolidation instead: skills and a persistent wiki co-evolve, with the wiki compressing what past runs learned and the skills refined against it. Between them and ContextPilot-14B, which puts the offload decision in the weights, the field now has three distinct answers to the same question — file, wiki, or checkpoint — which is roughly the same unsettled state the framework comparison reached. The contrarian position got its clearest statement on Sep 9. Ben Dicken argues the cleanest agent memory system is an ordinary database — Postgres, SQLite, MySQL or DuckDB holding messages, logs and operational context — with the agent constrained by views, scoped credentials, result caps and short timeouts.

The claim is not that databases retrieve better; it is that the hard part was always governance, and a database is the one component in this stack that already has inspectable, enforceable limits. Set against Memoryfields' Markdown-plus-SQLite files and funes' cross-agent layer, it is the same instinct arriving by a third route: agent memory keeps converging on formats that a human can read and an administrator can restrict.

Frameworks & infrastructure

The Model Context Protocol (MCP) is the connective tissue most frontier labs are standardising on. Anthropic shipped MCP tunnels with Opus 4.8 to let agents reach servers inside private networks without exposure. Self-hosted sandboxes for managed agents are now in beta, addressing the "where does the agent's code run" problem. Ollama's Cloud now exposes MiniMax M3 directly through three agent harnesses (Claude Code, Hermes Agent, OpenClaw) via single-command launches, lowering the friction of swapping models inside an existing agent loop. A distinct framework-ergonomics line argues the abstraction itself should be lighter: Vercel's open-source Eve (June 17) defines an agent as a directory of files rather than a class, graph, or config — the framework compiles the directory, wires up durable execution, and connects channels (Slack out of the box via Vercel Connect) automatically — so an agent becomes a versionable, diffable filesystem artifact deployable in one command.

On the multi-agent side, Nous Research's open Hermes agent made its delegate tool spawn subagents asynchronously (June 16): background agents run research, refactors, builds, or analyses in parallel while the parent chat stays responsive, removing the synchronous-delegation bottleneck that had capped Hermes parallel workstreams. Remote, persistent execution is becoming a standard harness feature rather than a differentiator: Mistral's Vibe Code Mode (July 16) gives its coding agent a dedicated web surface where sessions run in parallel, keep running while the developer's machine is off, execute in isolated sandboxes, and connect to GitHub through to a pull request — joined by a VS Code extension for in-IDE use and a CLI /teleport command that moves a live session between terminal and cloud without losing history or approvals. It mirrors the runtime problem OpenAI is solving by folding Ona into Codex (see Industry & business), suggesting "where does long-running agent work actually live" is converging on the same answer — a persistent, portable cloud session — across vendors.

NVIDIA opened its own foundation-layer answer on July 21 with the Agent Toolkit — an open foundation of models, tools, skills, and a secure runtime aimed at helping enterprises build specialized agents tuned to domain-specific workflows — and two days earlier extended agentic AI into a new modality, shipping vision skills such as Multi-View 3D Tracking (MV3DT) that let coding agents (Claude Code, Codex, Cursor) build full video-analytics pipelines from a plain-English prompt. The aggregation layer that OpenRouter built for models is now being rebuilt one level up, twice over. AgentSky (Aug 27) puts Claude Code, Codex, Hermes, DeepSeek Harness, Kimi Code and opencode behind a single API in which the agent and the model are selected in the same request, with the cloud machine and session state managed for you; Monid does the same for tools, exposing 1,700+ across search, social, video, data and sales behind one key with per-call prices shown before the agent chooses.

Both make the harness a runtime decision rather than a build-time commitment, which is what anyone comparing coding agents one at a time actually wants — and both concentrate a new dependency in exactly the place the Stripe/OpenRouter acquisition showed is worth owning. The layer those runtimes keep deferring is credentials, and LangChain's Connections (Sep 10) is the first managed answer with the right distinction built in. It separates an agent-owned secret — one key the agent uses for everyone, appropriate for a web search — from a user-owned OAuth grant the agent borrows for the duration of one caller's request, appropriate for filing a ticket as the person who asked. Per-caller identity is what makes the second case auditable rather than a shared service account with a name attached in the prompt. It pairs with Vercel Connect, which attacked the same problem along the lifetime axis by issuing task-scoped credentials that expire, and it fills exactly the hole Agent Plugins 1.0 left open when it standardised what an agent can do and left on whose authority to each client.

Aggregation continued one modality at a time on Sep 16. ElevenLabs put more than fifty creative models — speech, transcripts, dubs, music, sound effects, images and video — behind a single MCP server, so an agent addresses one tool surface where a person previously moved between five products. It is a narrow, genuine convenience for media workflows and a familiar structural bet: the same move AgentSky made for harnesses and Monid for tools, applied by one vendor to its own catalogue. The difference worth noting is who benefits from the concentration. AgentSky and Monid aggregate across vendors and are therefore substitutable; a vendor aggregating its own catalogue behind the protocol makes the protocol the integration point and itself the only thing on the other side of it. That is not an argument against adopting it, but it is the reason MCP endpoints are becoming the dependency worth auditing rather than the neutral plumbing they were introduced as.

Two Sep 16–17 arrivals show the protocol being adopted from the other side — not by agents reaching for tools, but by systems publishing themselves as tools. Google opened early access to an MCP server for Google Home, so an outside agent such as ChatGPT can drive every device in the ecosystem; the setup deliberately is not consumer-grade, requiring a Google Cloud project and a manual handover of connection details, and it is limited at launch to US subscribers of Google Home Premium Advanced. Stanford's Paper2Agent does the same thing to the scientific literature: it reads a paper and its repository and emits a tested MCP server, producing a 22-tool AlphaGenome agent in about 45 minutes for US $14 and converting 74 of 100 bioRxiv papers attempted. Read together they mark a shift this section has been anticipating since the MCP roadmap. The interesting MCP servers are no longer wrappers somebody wrote to make an API agent-legible; they are the canonical interface a platform or an artifact ships. That changes the auditing question from “which servers has this agent loaded” to “what does this platform let an arbitrary agent do once it is connected”, and Google Home answers it with a device ecosystem.

Agent-net's Webagent (Sep 14, Apache 2.0, still v0) attacks the same surface from the safety end. It turns any website into an agent described by one JSON spec with nine pluggable slots, one provider each, and routes every tool call through action.Guard before execution. That is the structural version of an instruction this page keeps seeing written into prompts: the check cannot be skipped by a model that reasons its way past it, because the harness performs it. Placed beside Google Home's open control surface, the pairing is the honest shape of where this is heading — platforms publishing broad capability through the protocol, and harnesses having to supply the chokepoint the protocol does not define.

The agentic harness

The "harness" — the scaffolding around the model that supplies tools, skills, memory, a sandbox, and permissions — is increasingly treated as a distinct, standardizable layer rather than bespoke glue, and on Sep 11 OpenAI put a price on it. The Agents API exposes the harness that runs Codex as a product in its own right: environments, files, tools, MCP servers, up to three concurrent subagents, execution that survives across context windows, automatic compaction, tool discovery deferred until a tool is needed, and tool results combined in code rather than round-tripped through the model. It bills nothing for the harness itself, only for the models and tools it calls, which is a deliberate position — the scaffolding is the moat and the giveaway at once. The commoditization thesis this section has carried gets its sharpest test here: if a lab will hand you its production harness for free, differentiation has to come from somewhere else.

Anthropic's Claude Managed Agents (public beta, shipped with Fable 5) is a managed version of this layer: a long-running-agent harness that works out of the box with the new model and bundles fallback handling. Practitioner writing (Decoding AI Magazine's component-by-component teardown) makes the broader argument that, just as base LLMs commoditized, the harness is hardening into a handful of batteries-included frameworks — which pushes differentiation up to model selection, context engineering, and memory rather than the loop itself. See Tools & DevEx for the build-vs-buy framing. A concrete instance of that commoditization landed July 16: SpaceXAI open-sourced Grok Build, the Rust-based terminal coding agent behind its grok CLI, under Apache 2.0 — the harness (full-screen TUI, agent runtime, and file-edit/shell-execution tool layer), not the model. It runs interactively, headlessly in scripts, or via the Agent Client Protocol (ACP), and syncs periodically from xAI's internal monorepo. Decoupling a permissively-licensed harness from the weights it was built around means anyone can now run xAI's exact coding-agent runtime on top of a different model entirely, which is precisely the "harness as commodity component" trajectory this section has been tracking.

Two July 21 essays sharpen the argument from opposite directions. Decoding AI's Paul Iusztin argues that as frontier models commoditize, the harness is what a builder actually owns — Claude Code, Codex, and Cursor are, in this framing, different harness implementations wrapped around the same rentable frontier models — and continued the point July 22 with "Building a Coding Agent From Scratch," a walkthrough of designing a harness around the model from the basic agent loop up to a remote swarm. Vanishing Gradients' Hugo Bowne-Anderson pushes back on the implied prescription that more scaffolding is always better: the right amount of harness complexity depends on the agent's actual action and context complexity, not a default checklist applied regardless of task. Read together, the harness is being treated as the load-bearing, ownable layer — but "more harness" is not automatically the right answer.

A third essay (July 28) turns the argument into a working framework: agent design should be mapped along two axes — context complexity (how much information must be assembled, carried forward, or retrieved) and action complexity (how many tools an agent selects, sequences, and verifies) — with the harness responsible for five runtime jobs: running the reasoning loop, executing tools, assembling and managing context, persisting state, and enforcing boundaries. The piece is explicit that Pi, OpenClaw, Codex, and Claude Code illustrate these trade-offs rather than prescribe them; a 147-line four-tool agent (Read, Write, Edit, Bash) is offered as proof that a minimal harness, not an elaborate one, is often the right amount of scaffolding for a given job. A fourth installment (July 28), Paul Iusztin's "The Bare-Bones Coding Agent Loop," approaches the same point from the build side rather than the design-framework side: a minimal reference implementation — one agent loop, nine tools, running in a steerable terminal — meant to make explicit what Claude Code and Codex actually do under the hood, rather than treating their architecture as something to reason about only from the outside.

Two September releases take that minimalism past the reference-implementation stage into things people run. hip-agent (Sep 8) is a harness written for agents rather than humans — configuration is environment variables, actions are shell commands, a subagent is a child process, and everything else is delegated to protocols that already exist — leaving a core loop of roughly 200 lines of Python plus a Codex API module. Headlong (Aug 27) is stranger and more interesting: under 10,000 lines of Bash, built around a persistent thought loop, so the agent is always running and an incoming message is an observation rather than a trigger. That inversion matters for anything meant to run continuously rather than per-task, and it is the sharpest available counter-argument to the position that unavoidable complexity belongs in core abstractions — here there is almost no core to absorb it. Against all of this sits the YC claim that harness work outperforms model upgrades on reasoning scores, which, if it holds, makes the size of the harness a question about maintenance rather than about capability.

YC has now put a second, blunter number beside that claim. Garry Tan reports (Sep 14) that at the latest demo day almost every non-hardware startup was building a domain-specific harness rather than a model or a thin application over one. The argument for concentrating investment there is portability: tools, files, memory and the logic that decides when a job is finished are where knowledge of how a job is actually done in one industry lives, and a harness that encodes it survives swapping GPT for Claude underneath. It is one investor's read of one batch rather than a measurement, and it should be read alongside the commoditization thesis above rather than as confirmation of it — if OpenAI will give away its production harness, the differentiating layer has to be the domain content poured into one, which is precisely what these startups are betting. The consumer-scale version of the same architecture arrived from an unexpected direction: Apple's Model Delegation (Sep 14) registers Claude as a Siri extension in the same way ChatGPT already is, with the delegated model handing tasks back whenever a request needs an Apple system feature, and a separate inference-provider option able to replace Apple's own server-side Siri model outright. The hand-back boundary is the transferable idea — the swapped-in model gets the reasoning and the platform keeps every capability that touches the device, which is the cleanest statement yet of what a harness owner retains when the model becomes interchangeable.

A day later LangChain published the build order this whole argument implies, and it is short enough to be checked against your own harness. Sydney Runkle's guide reduces the job to three moves: start bare, with create_agent wiring a model to a few tools and a prompt and running the loop itself — pick a tool, check the output, decide the next step, repeat; add middleware, framed explicitly as everything a prompt cannot do, which is trimming context before it overruns, retrying failed tools, redacting sensitive data, pausing for human review, and capping spend; then fit the harness to the specific task rather than building one generic wrapper, because a support agent and a coding agent do not need the same scaffolding. The middle move is where the section's whole thesis lives. Every item in that middleware list is a failure mode this page has documented separately — context exhaustion, unhandled tool errors, data leaving through a trace, unattended destructive actions, unbounded cost — and naming them as a standard layer rather than per-project glue is what turns “the harness is the product” from an observation into something with an interface. Runkle's stated conclusion is the same one Iusztin and Bowne-Anderson reached from the essay side: a capable model is a starting line, and the leverage is in the tools, context, guardrails and workflow wrapped around it. What is new is that it now comes with a quickstart, which is how a thesis becomes a default.

Cognition's Devin Fusion (Sep 16) adds the piece the routing literature keeps leaving out. A frontier model acts as lead — planning, reviewing, and reclaiming control when it needs to — while execution is handed to a smaller, cheaper model, and Cognition is pointed about what this is not: a one-shot router that picks a model at the start and lives with the choice. Every cost-tiered design on this page commits to a difficulty guess before the work begins and has no recovery path when the guess is wrong, which is exactly the shape of Spotify's honest caveat that its cheaper reader missed a thread-safety bug the frontier model caught at once. Fusion makes escalation continuous instead of a single decision, and pays for it by keeping the expensive model resident across the whole run rather than only on the steps routed to it. Set beside Google Cloud's reversibility rule directly below, the two are different answers to the same question about when the cheap model should not be trusted: Google decides in advance from a property of the action, Cognition decides continuously from what the work is producing. Neither has been measured against the other, and Cognition published no comparative cost or quality figures with the release, so what exists so far is a design argument rather than a result.

Agent loop design & reliability

As the harness commoditizes, attention is turning to designing the agent's control loop rigorously and making it self-correct. On design, a "loop engineering" discipline reframes agent building around the plan → act → verify → repeat loop rather than one-shot prompting; grounded in Karpathy's autoresearch repo and the Bilevel Autoresearch paper, it names three primitives that actually make loops work — verifiers, persistent state, and well-defined stop conditions — the difference between an "autonomous agent" and one that runs until it exhausts its token budget. On reliability, Stanford's TRACE turns an agent's own recurring failures into training signal: it detects a repeated failure mode, auto-generates a capability-targeted RL environment around it, and trains a LoRA adapter to patch that exact gap, so the loop improves where it keeps breaking instead of being re-prompted. (RL/training detail on the Training & RL page.) The August work pushes the same instinct one level further out, to the agent's design rather than its runtime behaviour. Rather than reasoning about which structure ought to be fastest, a genetic coding-agent loop generated diverse candidate designs, kept strong performers and mutated or recombined them across generations; the winner cut a CLI's startup from 142.0ms to 98.6ms and was not among the designs anyone would have written down first. Two guardrails carry the result: binary gates that exclude broken variants outright, and a numeric rubric frozen before results appear, so the criteria cannot quietly drift toward whatever the search produced — the failure mode that makes most self-improvement claims unfalsifiable. File-based results keep an audit trail, survive crashes and keep parallel sub-agents isolated. Read next to the finding that memory-based agents' gains largely dissolve under shuffled task orders, the pattern is consistent: agent self-improvement holds up exactly to the extent the measurement was fixed in advance.

Compaction has been treated on this page as a scheduling question — SelfCompact's contribution was better criteria for when to compact — and a September run shows the other half of the problem is unaddressed. Simon Willison gave ChatGPT Work with GPT-6 Astra a one-sentence brief (5K and 10K running loops from his house, using OpenStreetMap) and got back a correct answer after 27 minutes: address resolved through Nominatim, roads and trails pulled through Overpass, loops computed locally, results delivered as an embedded D3 map with GPX and GeoJSON downloads. The code that produced it was never shown in the interface, and when he asked for a copy the thread had compacted and it no longer existed. The requirement he draws from it is specific and applies to every harness here: a system that compacts must preserve the pre-compaction text and make it reachable through a tool call. Until it does, compaction is lossy in the one direction that matters for verification — the loop keeps the conclusion and discards the working, which is the opposite of the ordering a verifier needs, and it turns a long autonomous run into a result nobody can reproduce or audit.

Meta-orchestration & governance

A layer is forming above individual coding agents: tools that compose, govern, and share multiple agents as one system. Two Sep 11 entries stake out its opposite ends. Cursor Projects is the coordinator taken seriously — a persistent agent that retains months of context, fans work out to thousands of subagents, and is triggered by Slack messages, schedules and pull requests rather than by a human turn; AWS's Pizza Bot is the inbox that makes such a fleet legible, with finished runs in Unread, runs awaiting approval in Action, tasks started from prompt, schedule or webhook, on-disk checkpoints that survive a closed tab, and delegation to specialists defined with MCP and Agent Skills. Between them they name the two problems this layer actually has: dispatching work, and knowing what came back.

Google's survey of its agents challenge is the corrective — across thousands of submissions the durable patterns were bidirectional MCP, event-driven concurrency, fallback-model output validated as strictly as the primary's, and cheap routing before expensive calls, with one team absorbing more than 40% of requests in a zero-token regex layer. More orchestration is not what distinguished the winners. Databricks' Omnigent (Apache 2.0) is the reference example — it sits above Claude Code, Codex, Pi, and custom agents and provides four things teams running several agents currently lack: composition (chaining agents into one workflow), governance (unified access control, audit logs, cost caps), sharing (publishing agent configs across teams), and a single control surface over otherwise-siloed agents. Adjacent entries target neighbouring slices of the same layer: OpenRouter's Fusion for multi-model routing/fusion and Bastion for agent isolation. The strategic read (per MarkTechPost's June 2026 "agent stack" map) is that investment is shifting from the base-model layer to this control layer — once agents and harnesses commoditize, the orchestration and governance tier becomes where differentiation and lock-in accrue. (DevEx/build-vs-buy framing on the Tools & DevEx page.) Two August items give this section its first hard numbers and its first credential architecture. A paper on a policy algebra for trust-preserving agentic execution (Aug 19) enforces permissions across an entire task instead of at invocation — its worked refund agent reads one customer's record, stays under a spending limit, escalates to a human when required and leaves an audit trail under one composed rule set — and reports stopping or correcting 94.8% of rule-breaking actions while completing 86.9% of legitimate ones.

The gap is the finding: continuous enforcement currently costs about one legitimate task in eight, which is a tractable price to argue down rather than a reason to abandon the approach. OneCLI (Aug 20) supplies the deployment shape: a sandboxed agent per employee, a gateway that injects credentials so no agent ever holds one, and an outbound-only runner with no inbound ports, all on the company's own infrastructure. Meta's Sentinel agent inspecting Muse's outbound traffic is the consumer expression of the same principle — the check has to live outside the thing being checked.

Google's Agent Anomaly Detection (Sep 17, private preview on the Gemini Enterprise Agent Platform) adds the piece this section has been describing in the negative: detection after the fact, over fleets nobody can watch by hand. It monitors deployed agents for anomalous behaviour using the logs and traces the platform already collects, and flags suspicious activity rather than blocking it. The economics are attractive precisely because it reuses the debugging artifact — there is no separate instrumentation pass to fund — and that is also its limit, since it can only see behaviour the harness happened to record. Set against the policy-algebra numbers above, the two occupy different positions on the same trade: enforcement pays about one legitimate task in eight to stop 94.8% of violations in flight, while anomaly detection costs nothing at runtime and catches only what the logs betray afterwards.

Agentic search

"Agentic search" is used for three distinct implementation patterns, and conflating them causes confusion (per Doug Turnbull's June 8 teardown): retrieval-centric (build good search so the agent can fill in missing context), harness-centric (steer the agent toward the context it needs even when the underlying search is weak), and model-centric (fine-tune an LLM to know how to search a specific corpus). The unifying problem is that agents lack domain intuition about what a given user finds relevant and will confidently go astray without context engineering. This complements the Agentic RAG work below, which is largely a harness-centric instance of the pattern.

Browser & computer-use agents

Microsoft Fara1.5 is the most recent open-weights browser computer-use family (4B/9B/27B), reported to beat OpenAI Operator and Gemini 2.5 on certain tasks. The space is becoming crowded enough that open models are credible alternatives to proprietary browsing agents. Perplexity’s Personal Computer (July 31) pushes past the browser entirely: an agentic layer that treats the operating system itself as the agent’s surface, positioning Perplexity’s agent as a general-purpose digital worker. The more consequential shift is the site meeting the agent halfway. Browser Use added WebMCP support (Sep 8), so a website can expose its actions directly and the agent calls the intended interface instead of running screenshot-and-click loops against a layout it has to infer — the same bet ChatGPT made on WebMCP in late August, now in an open automation stack. It only helps where sites cooperate, so pixel-level computer use remains the fallback for everything else; but it changes what a well-behaved site looks like, and it removes the class of failure where the agent is defeated by a redesign rather than by the task.

Browser Use’s jev-ultrafast (Sep 20) attacks the cost this section keeps naming: a browser agent spends most of its wall-clock waiting on a reasoning call before each click. Handing the choice of operation and target to Jev and calling a text model only when something must be typed, it found a Google Flights itinerary in 7.073 seconds across 17 Jev requests at a median 178ms. The structural claim underneath is that most steps in a browser trajectory are selections among visible options rather than judgements about the page, and selections are exactly what a typed-decision model returns. Where that stops being true — a page whose next action depends on a model of the whole site — is measured elsewhere: Context7 found the same model at 27% against 93% on crawl-root selection while running 10–170× faster. The two results together give this thread its first honest boundary rather than another latency headline.

Where a site will not cooperate, the remaining obstacle is not layout but authentication, and Tencent's BrowserSkill (Sep 17, 3.5k stars) is the bluntest answer yet: let the agent use the browser profile that is already logged in. Claude Code, Codex, Cursor and other agents drive a separate window against the existing profile rather than seizing the session the person is working in, and control returns to the human for CAPTCHAs and approvals. It works, and it is worth naming what it costs. WebMCP and Connections both push toward an agent acting under an identity that can be scoped and revoked; BrowserSkill hands over the user's whole browsing identity for the duration, with the separation enforced by window management rather than by permissions. For a personal machine that is a reasonable trade; as a deployment pattern it is the credential problem OneCLI was built to eliminate, reintroduced for convenience.

Agent extension patterns

An open practitioner debate concerns when to extend an agent via an MCP server, a CLI tool, an agent skill, or a custom tool. There is no consensus framework yet; the choice depends on whether the extension needs nuanced reasoning, deterministic execution, or shared distribution. What did settle is the packaging question underneath it. Agent Plugins 1.0 (Aug 13–14) stops treating skills and MCP servers as separate distribution problems and puts both inside one directory structure with a shared manifest, so a deployment assistant combining reusable instructions with live tools travels between compatible clients without being repackaged for each. Client-specific behaviour lives in namespaced folders that unsupported clients ignore, and installation, permissions, trust and runtime behaviour stay with the client rather than being dictated by the format — a deliberately narrow portability layer that leaves room for clients to differ. The unresolved piece is authentication, which is the part that decides whether a portable plugin is safe to install, so the standard currently makes distribution easy and leaves the trust decision exactly where it was.

On-device & local agents

A local-first agent stack is emerging as a credible alternative to cloud agent loops. OpenJarvis (Stanford/Lambda) decomposes a personal AI into five swappable primitives — Intelligence, Engine, Agents, Tools & Memory, Learning — and uses a cloud model only as a search-time teacher to find a good "spec," then runs entirely on-device with zero cloud calls (Apache 2.0; the gap concentrates on reasoning/research-heavy tasks). Kimi.ai's Kimi Work extends the pattern to a desktop "agent swarm" — up to 300 agents running in parallel on a local machine, paired with a WebBridge browser extension to autonomously navigate, search, and scroll websites. Paired with laptop-class multimodal models like Gemma 4 12B, the marginal-cost and latency advantages are large, which is pulling some agent workloads off rented GPUs entirely. Andrew Ng's OpenWorker (July 25) extends the pattern to a desktop deliverable-producing agent: MIT-licensed and local-first, it returns a finished artifact — a polished document, a filled spreadsheet — rather than a chat reply, working across 35 app connectors while keeping data on-device.

Meta’s Muse for Mac (Sep 19) is the desktop version of the bargain this section tracks: an agent reaching files, mail, messages, calendar and notes, with opt-in access, optional Full Disk Access, explicit approval for deletions and sends, and a secure VM isolating the data from other users. The clause that decides what the isolation is worth is Meta’s own — it can still access the data when needed to operate the service — which is the standard carve-out and the reason “local agent” and “agent running on your machine” are not the same claim. Free, macOS, US only. Read against Google’s family agent the same week, which went the other way and gave the agent its own cloud computer and Google account, the two bracket the identity question this thread has been circling: either the agent borrows a person’s authority and you constrain it with prompts and dialogs, or it gets its own and the permission boundary becomes a property of the account.

Agentic retrieval

Retrieval is shifting from a single embedding lookup to an agent that plans and iterates. Google Research shipped an Agentic RAG framework into Gemini Enterprise: a multi-agent workflow that plans, rewrites, and re-searches until the retrieved context is complete before answering, raising factuality accuracy by up to 34% over standard RAG and hitting 90.1% on cross-corpus retrieval — with a "Sufficient Context Agent" that simply won't answer until it has enough information, cutting hallucinated citations from incomplete retrieval. Complementing the framework approach, Harness-1 (20B) is a retrieval subagent trained with reinforcement learning inside a stateful search harness (on GPT-OSS-20B), reaching 0.730 average curated recall by learning how and when to search rather than just what to fetch — weights and harness code open. See Training & RL for the training-harness angle and Tools & DevEx for the knowledge-graph memory substrate.

Multi-agent orchestration

Beyond single-agent loops, practitioners are assembling small teams of specialized agents that collaborate across product/research/dev/eval roles. A worked example is a six-agent Claude Code team backed by a Neo4j-style knowledge graph for shared, typed memory — turning multi-agent coordination from a research demo into a shippable pattern. The hard parts are the memory substrate (see Tools & DevEx → knowledge-graph hygiene) and verification, not the orchestration itself. Late August produced a cluster of answers to the coordination half that all chose the same venue: the chat the team already uses. SandboxAQ open-sourced Switch to bring agents from Claude Code, Google ADK, LangChain and OpenAI into Slack, Teams and Discord with shared history and rules; AgentConnect covers Slack, Telegram, Discord, Lark, GitHub and GitLab for any ACP-compatible agent; and Concord is an MCP server letting Claude Code, Codex and Cursor message each other directly. Putting coordination in a channel makes it auditable and gives humans a place to intervene, which is the property a shared scratch file never had. It also inherits the channel's failure modes — and, given the agents that used a public wiki as a message board, an agent-writable shared surface is now a thing to threat-model rather than assume. Foreman (Aug 14) answers the same coordination question with a pipeline rather than a channel: tasks arrive from GitHub and Linear and pass through four fixed stations — Classifier triages, Analyst produces a plan with explicit acceptance criteria, Implementer executes it in its own sandbox, Reviewer judges the output against the real diff — leaving humans to review, mark ready and merge. The structural choice worth copying is that the Reviewer is a separate station with its own context rather than the Implementer checking its own work, which is the verification half the knowledge-graph pattern above leaves to the reader. It also trades the channel's auditability for a narrower blast radius: a fixed pipeline cannot be written to by an arbitrary agent, but it also cannot be joined by one.

Agora (Sep 18) proposes a different exchange format for multi-agent research: an append-only Git DAG in which hypotheses, results, verifications and reports are commits. The property that buys is provenance — every claim carries a parent and a hash, so a later agent can inspect what a result was derived from instead of trusting a summarised scratchpad, which is the thing shared-memory designs give away and the thing the machine-produced-proof disputes keep turning out to need. It is a repository with no throughput or quality numbers attached, so what is on offer today is the data structure and the argument for it, not evidence that agents coordinate better through it.

Orchestration across vendors got its first vendor-published recipe on Sep 15, and the routing rule in it is better than the one this section has been assuming. Google Cloud's guide to running Gemini and Claude inside one agent workflow uses Gemini 3.8 Flash as the fast, cheap worker for routine steps and escalates to Claude Fable 5.1 for work that is harder or irreversible. Cost-tiered routing — Spotify's Portal, Uber's agent bill, the subagent-model switch on the Tools & DevEx page — all split on expected difficulty, which the harness has to guess. Reversibility is a property of the action itself, knowable before the call is made, and it aligns the routing decision with the blast-radius principle that governs human review of agent output: spend the expensive resource where a mistake cannot be undone. The guide's other instruction is the one most likely to be skipped and most likely to matter, which is to benchmark both models on your own tasks rather than inherit a published ranking — without that the thresholds rot silently as models change underneath them. That a cloud vendor is documenting how to hand a competitor the consequential half of the work is the structural datapoint: at this layer a model is a component with a price and a risk profile.

Two Sep 16 items move this section from dispatch to supervision, which is where the unexamined failures have been. Nous Research refactored Hermes with 1,393 agents at about $19,000 in tokens and published the procedure: plan, shard carefully, review every shard, reconcile conflicts, and expect strange breakage when hundreds of workers touch one repository. That last clause is the finding, because it is not a story about an agent going wrong. It is what happens when many agents are each individually correct about overlapping regions of the same codebase, and no orchestration design catalogued above has an answer for it — the channel designs make coordination auditable and the pipeline designs make it narrow, but neither reconciles concurrent correct edits. Alongside it, a circulated Codex pattern supplies the cheap version of the same instinct: Astra orchestrates, Sol and Luna execute, and a 15-minute heartbeat inspects progress and corrects course while the workers are still running. Against Foreman's Reviewer station, which grades a finished diff from fresh context, the heartbeat is the complement rather than the rival — supervision of work in flight against inspection at the end — and on a refactor or a video edit, discovering drift an hour later means an hour is gone. What neither has is a justification for its parameters. Nobody has measured what heartbeat interval costs less than the drift it prevents, and $19K for one refactor is a floor for swarm work rather than a result, but it is the first published number of its kind and every efficiency claim at this scale now has something to be measured against.

Agentic domain applications

An emerging thread is treating "agentic X" as a domain reframing rather than a tooling story. Hugo Bowne-Anderson argues agentic data science should restore the original promise of data science — better decisions, not faster code — by combining agent harnesses with causal eval layers and chat-interface dashboards. The pattern generalises: domain-specific agent loops with their own verification and observability rather than generic coding agents pointed at domain problems. A shipping instance of that pattern is Synthetic Sciences' OpenScience (Apache 2.0): a model-agnostic, self-hostable workbench that runs the full scientific research loop — literature review, experimentation, and paper drafting — across ML, biology, physics, and chemistry. Where every major lab has built an internal, closed "AI scientist," OpenScience is the first credible open equivalent, letting academic labs get agentic research tooling without vendor lock-in. Hugging Face put the hosted version of the same idea into its chat window on Sep 10: an autonomous ML engineer that takes a plain-English brief and runs literature research, dataset construction and model training through to a working demo published on the Hub. The operational detail worth copying is not the autonomy but the governor — the user sets a compute budget the agent is held to, and each run gets its own dashboard. Long-horizon agents that train things are the class where cost failure is silent until the invoice, and treating the budget as part of the task specification rather than as monitoring after the fact is the first mainstream attempt to make that a bounded risk.

Google’s family agent (Sep 18) is the household instance of the same pattern, and its design choice is the interesting part: the agent runs on its own cloud computer under its own Google account rather than inside a family member’s, turning a household’s shared mail, files and calendars into daily briefings and updated plans for up to six people, filling in forms and coordinating activities, and asking permission before acting outside the group. Giving it a separate identity makes the permission boundary enforceable at the account layer instead of by instruction, which is the conclusion Meta’s Sentinel reached the same week from the security side. It is a waitlisted US experiment with no reliability data, so what is recorded here is an architecture, not a working product.
